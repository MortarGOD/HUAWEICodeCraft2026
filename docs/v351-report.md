# v351：校准内精确K缓存与factor守门精简

算法父版v350；Linear/Q/K/V量化参数、factor回归、搜索轮数和守门阈值均不变。默认solution.py未覆盖。目标为降低校准重复计算，不是新精度算法。

## 复用边界

缓存只在一次Attention校准调用中启用，目标限定为factor拟合/留出用到的原校准K输入。输入对象匹配后仍逐值比较输入快照，完整state逐类型/逐值比较，维数必须相同；命中才返回保存输出的独立副本。状态变更、输入变更、非目标输入均正常计算。保留最多6项、Tensor快照payload最多64MiB（不含Python对象开销）；容量超限逐项淘汰，单项超限不缓存。

缓存不进入返回state。正常/异常退出均清空entries和targets，并令活动缓存为None。测试接口不启用缓存；保留的诊断只有次数/峰值字节等数值。没有I/O、额外依赖或跨测试接口数据传递。

同时合入已验证的factor-only守门精简：删除不用的交叉梯度、二阶统计、重复概率和概率L1诊断，不改变最终PV损失及采用条件。

## 先验审计与验收

只读审计6组中4组发现新分支3次K调用均有父校准完全相同输入/state结果；所有命中输出相同。未命中组不假定可复用。审计覆盖公开K入口，不声称覆盖所有私有别名。

正式文件260项数学/强制接口/缓存检查通过；官方mini22/22。额外缓存检查包含返回值修改隔离、原位state/输入/scale变更、维数变更、6项上限、超64MiB旁路、非校准直通。父版v324 AST前缀除文档保持不变；新的公开K包装器非校准时直接调用v350原K路径，实际逐值等价仍需后续回归。

31796b6推送后，实际v351文件在两套bank共12组60例K/V对照、校准state逐值比较及异常清理全部通过，并完整复测一次。每轮60个K输出+60个V输出均与独立加载的v350相同；260项检查及mini22/22仍有效，源码未改。不是全量300题/96核验收。

## 性能证据与限制

每轮校准命中49/114次目标K调用；峰值Tensor快照payload64,913,416字节，低于64MiB上限。缓存也复用了父校准内部的重复调用，49次不全是新factor分支命中。

首轮完整校准合计24.992270→25.190554秒，未提速，首组有明显波动；原始数据保留。复测23.208495→21.350063秒，约快8.01%。这是校准时间，不是总提交时间提速8%。只有两轮、每组交替版本先后，不能当稳定置信区间。

仅作条件估算：把复测按bank得到的校准倍率0.94185/0.89062作用于此前v350的校准部分，动态时间保持此前记录，再以父版246秒缩放，得到约265/267秒。这混合不同运行的局部计时，不是完整部署实测；首轮未提速是重要反证，线上仍可能接近此前291秒或超时。预计精度与v350相同，仅限已验证样本逐值证明，v350本身尚无线上分数，不能承诺22000。
