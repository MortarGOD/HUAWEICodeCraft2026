## 机制

`hif4_calibration_attention` 把 logit 空间 Hessian 以 bf16 写入状态：

```python
Hk_bf = Hk.to(torch.bfloat16).contiguous()
Hq_bf = Hq.to(torch.bfloat16).contiguous()
```

`_refine_attn_heads` 随后用它引导格点精化（`gw = H[hv].float()`），翻转判据是

```
J 的增量 = 2·s·d·M + d²·H[c,c],      M = dq @ H
```

bf16 只有 8 位尾数：H 的每个元素在被提升回 fp32 之前就被扰动约 **0.4%**，而贪心翻转比较的正是
远小于此的余量——判据接近抛硬币。本版改为 fp32 携带，判据使用与拟合同精度的 Hessian。

## 局限

- 本地增量不换算为线上保证；485 点标定误差大于第 1 档的余量（+82）。
- 独立库给 −44.8，方向相反。
- 动态度量：本候选只改校准期携带精度，动态路径计算量不变（`_refine_attn_heads` 本就把 H
  提升为 fp32，仅输入多了几位有效位）；`public_quantizer` 墙钟 72.7s 对 39.4s，属本机波动与
  5 case 规模差异，不构成 300 秒结论。
- 未在本轮刷新鲲鹏线上耗时；300 秒硬限仍需以线上为准。
