## 机制

`_VK_ROUNDS` 是 `_vk_fit`（**校准期**内核拟合）里迭代求解的轮数：

```python
for _ in range(_VK_ROUNDS):
    residual = probs @ error
    gradient = probs.transpose(1, 2) @ residual
    shift = shift + 0.75 * gradient / mass
```

内核从 V 特征回归 Q/K 的 logits，得到的近似 `P` 被 `_rb_refine` 用来把 V 的量化误差
投影出 `P` 的行空间（Round 8 的 `_VK_QUERIES` 是行数，这里是**内核本身的质量**）。
轮数 8 → 16 让回归更收敛 → 更准的 `P` → 更好的校正。

**动态成本不变**：`_VK_ROUNDS` 只在校准期使用，动态路径不增加任何开销。

**P 校正正在饱和**：`_VK_QUERIES`（行数）、`_VK_ROUNDS`（内核质量）、`_VK_RANK`（特征秩）
三者都作用于同一个"从 V 回归 P"的机制，各自有效但**彼此不叠加**；上限在 +460~470 附近。
第 3 档还差 +159，需要新的独立杠杆，而不是继续压这个机制的旋钮。

## 交付风险（沿用 v521 的说明）

`_rb_factor` 的 Cholesky 随 query 数立方增长。v525 与 v521 的 query 数都是 32、
动态成本相同（折算 ~+28.5s/250 题，单线程实测）。线上 261–269s、限 300s 的余量约 35s，
仍在临界区；外推依赖线上长度分布，本机耗时不直接换算鲲鹏线上。
