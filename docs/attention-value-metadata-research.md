# V 尺度树与舍入联合搜索：研究记录

2026-09-03。父版 v314=20071/241 秒；生产入口仍为已推送、待线上回执的 v315。Linear 不变，22000+ 目标尚未达到。本轮未创建新 solution 版本。

## 问题与算法

现有 V 均值反馈固定量化尺度，只改变整数码。新研究允许改变 scale_factor、scale_lv2、scale_lv3，并在每个新尺度树上重新优化舍入。候选最终按完整的 token×64 通道块组合，不能把不同尺度树的单个通道参数任意拼接。

沿用可由当前 V 独立计算的代理目标：

`L = sum_channels [mean_tokens(e)^2 + variance/T * mean_tokens(e^2)]`，其中 `e=V−Vq`。

这相当于均值误差与各 token 方差的混合，**不是实际未知测试 Q/K 的精确输出损失**。variance 比较 1 与 8，逐通道 MSE 上限比较父版的 1.01/1.1/4 倍。4 倍仅用于诊断限制是否阻断候选，未作为生产策略。

实现依次保留四个阶段，报告全部保存：

1. 将 V 加上通道反馈偏移后重新量化，重新搜索整棵尺度树。
2. 在新尺度树上增加 8 轮整数舍入反馈，再与父版比较。
3. 不提前按逐元素 MSE 淘汰尺度：显式保留父版六种尺度基底，各自反馈后选择。
4. 改为逐 token、逐 64 通道块选择候选，再检查跨 token 的精确代理目标，避免整段序列被迫使用同一个尺度基底候选。

第四阶段的单行变化公式是：设 `E=sum_tokens(e)`，改变量化输出 `delta`，则

`T² ΔL = sum_channels [(1+variance) delta² − 2(E+variance*e_row) delta]`。

多行同时变动存在交叉项，所以只将单行式用于生成候选；对全量、最多8行、1行三个更新预算，都重新计算真实代理目标和逐通道 MSE 保护后接受。并非把单行收益直接相加。

末份校准用父版实际部署 Q/K、完整 key、最多64个 query 检查真实 softmax·V 输出，两折都改善0.5%以上才按KV头启用。动态只访问当前 V 和固定校准 state。父版本身仍沿用自身校准流程，末份校准不是整个系统完全独立的留出集。

## 是否真的改变了尺度

`value-metadata-parameter-audit.json` 检查协方差组7：T=128/512/1024分别改变21/54/56个scale_factor元素，有效步长改变1176/3456/3584个元素；最大逐通道MSE比率分别1.0894/1.0795/1.0572，符合1.1上限。T=10只改变符号/尾数，T=1完全不变。因此该实现确实能动用尺度自由度，但本审计不是线上独立消融归因。

## 验证与限制

- 数学单行增量与直接重算在FP64下最大误差7.15e-13。
- T=1/17/129/1024/4097覆盖格式、边界回退、禁用路径、未激活KV头逐项不变、父参数不变、目标单调与MSE保护；额外使用合法但较差的父参数确认采用分支确实执行。
- 第二批反馈与协方差回归，两个版本合计20次完整state检查、350次动态返回格式检查通过；包括校准中的公开接口调用，不冒充350道独立题目。
- 多个实验曾并行执行，计时还包含验证/打分，不能据此判断线上耗时。本轮未完成候选独立性能评估、全250题验证或新版本self_check，不发布。
- 主入口和v315 SHA256仍为 `d85f87cc68ab4161056fb47b810be16d5465e12171ad86e3dda25db05c956fa6`。

## 下一决策

保留逐token尺度树组合能力，但不继续仅靠扩大候选/放松MSE限制堆小增益。更关键的是目标与未知Attention权重的关联：后续可将当前V可预测的K与校准Q分布结合，替换过于均匀的均值/方差目标；必须先验证预测精度。也不能因本地误差分解偏向V，就忽略线上已证明有效的Q/K GPTQ。待v315线上回执后才决定正式后继，不承诺22000分。
