## 扩大的范围

| 项目 | v421/v422 最后前缀搜索 | v423 追加搜索 |
|---|---|---|
| 通道选择 | 按单点变化排序的 8 个通道 | 每行 4 个锚，各选 4 个伙伴，最多 16 对 |
| 码值范围 | 每个码最多移动 ±2 档 | 每个通道全部 15 个合法码，每对 225 种组合 |
| 组合方式 | 一条排序路径的 8 个前缀 | 成对联合变化，允许两单点均无收益而联合有收益 |
| 通道跨度 | 可跨 64 块 | 可跨 4 通道微组和 64 通道块 |
| 激活行数 | ≤128 | ≤1024，同时限制 `N*I*O≤2^31` |
| 最终验收 | 原始 AW 与实际 BF16 乘积 | 同一目标，最多两个不同提案，逐行严格下降 |

v423 是在完整父结果后追加这一层，并未删除原有尺度/微组搜索。只修改激活的 sign/mant，每行至多两个有符号码发生变化，所有三级尺度与 W 固定。它扩大了候选空间及长度覆盖，但没有穷举所有通道对、同时修改多个通道对或覆盖所有矩阵形状。

设父激活解码为 Z、部署权重为 B、原始目标为 `T=A@W.T`，用 `r=T-Z@B.T`、`g=r@B` 和已有 `G=B.T@B` 生成提案。锚按单坐标连续潜力 `g_i²/G_ii` 排序；伙伴按两坐标连续二次型潜力排序，分母稳定化仅用于选择，不改变离散候选成本。对实际 BF16 逐级解码形成的改变量计算：

`Δ = -2*g_i*δ_i - 2*g_j*δ_j + G_ii*δ_i² + 2*G_ij*δ_i*δ_j + G_jj*δ_j²`。

每对全部 225 个组合参与比较，反向重复通道对、单坐标重复修改按稀疏编辑去重，保留每行两个不同的最优提案。FP32 增量只负责提案筛选；接受时对完整行数执行合法 BF16 解码与 BF16 GEMM，与原始 FP32 AW 比较逐行 MSE，打平或变差保留父结果。候选构造按至多64行分块，实际验收不裁剪行形状。异常、无改进、超出预算均回父。

沿用父版已有 teacher、部署 W、完整 Gram 和 marker，不增加校准包装器或 state。实际完整校准必须与父版逐字段相同，旧校准内部未启用 marker；默认入口、Attention 和 down 保持原样。整个源码是 v422 完整字节前缀加三个函数及父绑定。

## 历史与论文依据

[AQLM 原文](papers/quantization/text/AQLM_2401.06118.txt) §3.2、第399–519行把平方输出误差展开为单项和成对交叉项，并据此高效比较离散编码。本版迁移的是目标展开与增量评分；原文采用加性码本量化 W，本题采用固定 HiF4 码搜索 A，不能称复制 AQLM 码本或保证全局最优。

历史 v289 的微组 beam 仅 N≤10，以 Newton 三步长×两种 lv3 为候选；其跨块 beam 使用最初静态64通道量化库，都没有枚举当前相关标量对的全部225种码值，也没有使用当前末端 raw AW/BF16 验收。旧弱收益约束旧条件，不能证明所有更广搜索无效。替代解释仍保留：当前离散点已接近局部可达极限，扩大搜索可能只有小收益和明显额外成本。

## 机制与契约检查

[9 项测试](../tools/test_v423.py)及[结果](v423-tests.json)通过：

- 合法 metadata 下，225 种码组合的增量与显式 BF16 解码后的 FP32 乘积成本一致；两个保留提案确实不同。另有明确标注的非法 metadata BF16 算术压力样例，只验证舍入实现，不计入合法格式覆盖。
- 跨通道0/64的非贪心陷阱中，任意单通道15码都不改善，双通道组合把 SSE 从 0.0390625 降至 0.0078125；超过±2码的跳跃也实际生效。
- 预测改善但实际 BF16 GEMM 打平时回父；冻结输入、state、RNG和新模块重放通过。
- 129行强制机制样例全部生效，解码及验收始终保持129行。真实运行合成 NVFP4 校准与父版完全相同，新增搜索在校准内调用0次；129行动态量化123行改善、0行退化。这里的合成数据不是模型数据或线上覆盖。
- 行数和工作量边界、零值、非有限及数值异常回退通过。

官方 [self_check 日志](v423-self-check.log)为 6/6 接口、22/22 格式。通过临时目录唯一 `solution.py` 执行原始自检，未覆盖默认入口。

配对工具要求父子完整校准 bitexact，使用相同输入与 RNG 起点，并保持实际评分 dtype：原始 NVFP4 目标和 Algorithm1 基准为 FP32 GEMM，选手为合法 BF16 解码/GEMM，再算 FP32 MSE。逐行检查中任何正向误差差值均记录失败，容差仅作摘要，不作为放过退化的条件。

active 改变885个有符号码、737行；另一套改变28个有符号码、20行。两套最终实际BF16逐行MSE最大增量均为0；分别220和110项检查通过，所有组完整校准 bitexact、输入/state/动态RNG及跨样本和新模块重放通过。down 25题输出完全相同。源码运行前后与已推送hash一致。

active 的15道短激活up题有6题改善，增量 +0.000141674548；新增覆盖的10道长激活up题全部改善，增量 +0.000961919895，改变866个有符号码。新范围确实生效，但净收益仍小，不能据此宣称大量回收约600分。

## 开销与后续处置

4线程单轮纯接口时间（含校准，排除载入/评分/检查/重放）：active v422=36.340秒、v423=33.786秒；另一套20.155→14.983秒。完全相同的校准阶段就分别波动19.249→15.290、14.259→9.097秒，不能把全程时长差解读为新算法提速。单独计量的新增搜索合计为active **2.552秒**、另一套 **0.326秒**。

为覆盖大形状，[开销探针](../tools/profile_v423.py)在发布后使用合成相关BF16矩阵，预热一次、重复三次，只测新增helper，不含父搜索、校准和准备。四个形状均实际改进、0行退化：

|---|---:|
| 128 / 512 / 1024 | 24.18毫秒 |
| 512 / 512 / 1024 | 85.93毫秒 |

后两组达到 `N*I*O=2^31` 的工作量上限，验证了上限内的实际执行；超出边界的回退另由机制测试验证。这些合成矩阵不能代表真实模型分布或96核线上耗时，当前300秒硬限、280秒内部目标仍需线上回执确认。详见[开销原始记录](v423-search-overhead.json)。

处置：v422保留为已验证精度父版；v423已完成并可提交线上验证，作为搜索范围扩大而非收益保证。观察到的局部改善支持继续研究遗漏组合，尚不足以把剩余缺口主要归因于搜索不足。后续若回执只有很小增益或新增时间过高，优先检验更多通道共同改变/尺度与码联合选择的成本边界及固定W空间误差，不以简单增加循环次数替代新的机制；这些后续方向尚未实施，不宣称已经达到全局最优。
