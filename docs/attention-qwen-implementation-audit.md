## 1. 最重要的差别

文档给出的是从朴素量化器起步的路线图。当前实现早已具有离散尺度树搜索、Q/K 平滑和变换、GPTQ、输出 Jacobian、K 平移、V 均值协调、V 概率代理、相关残差搜索等组件。不能把它的 Phase 1–5 当作尚未开发的五大收益池；也不能因为当前组件更多，就认为当前算法已经最优。

文档遗漏的首要条件是：三次校准分别只有目标角色真实，其余角色是假对端；最终三个 state 来自三次不同校准。当前历史实现本身也仍有依赖这些假对端估计和选择的部分。配对校准下下降的输出 MSE，不自动等于线上有效目标；假对端来源、跨角色变换一致性、门控覆盖和统计迁移还没有被解决。最新六版的本地排序失效正是应认真承认的限制，不能用论文名称或实现数量抵消线上证据。

## 3. 最终绑定与当前有效链路

实际v435绑定：calibration在5325行；Q动态3494行；K动态4412行；V动态5331行。关键最终helper为 `_dyn_v:3592`、`_vk_fit:4689`、`_vk_probabilities:5085`、`_oj_fit:4628`。不能只读最后包装，亦不能把文件中已覆盖函数算作部署功能。

Q：BF16参考输入 → 通道平滑 → 全矩阵配平或正交旋转 → Q温度增益 → 六候选尺度树 → state允许时GPTQ → state允许时logit/Jacobian混合度量的非最近码搜索。T=1直接基础量化，因为此时softmax=1。

K：相同基础变换和GPTQ/lattice，另有KT/TS路径。KT可迭代去均值，TS用校准query probes估计当前K的权重，迭代求一个所有token共用的每head通道中心，随后重新用合法尺度网格量化（4255–4274、4348–4359）。连续层面 `K'=K−1cᵀ` 只给每行logits减相同常数，softmax不变；它不需要当前真实Q才能保持连续等价。**中心如何选才减少真实最终输出误差**仍受模型/量化/守门条件限制。这比文档只提通道缩放更直接对应softmax的平移不变性。

V：基础尺度树 → 全局通道均值/方差协调 → 若有kernel与active头则VK预测概率风险优化 → sigma情景处理回归不确定性 → 相关输出残差边界搜索 → v430对代理概率集中度调整（会被前述动态求P函数使用） → v435仅在非VK活跃头上做真实自身内容分区搜索。v430的温度只是V优化器内部概率代理的温度，不是修改评分端softmax；Q温度则是在合法量化之前调整Q输入，两者不同。

v435的内容目标是 `Σ_g S_g²/n_g + S²/T + SSE/T`；所有验收按实际BF16解码，保证每通道内容目标严格降、SSE和总误差和平方均不增；最多16通道、两轮、四个有利leader及全token伙伴。它不是任意真实P下输出MSE不退化保证，固定父state压力测试仍有3题退化（`docs/v435-report.md:44`）。

VR与VM源码保留在校准包装链中；但 `_VA_DROP='vr_vm'`，最终state剪去这两种部署路径（4730–4758）。故“VR/VM现在已上”若指动态最终输出是不准确的；内部校准仍可能受它们影响。v429 K quotient与v431–v434新树均未进入v430/435。默认v325保留的Q后置Newton尺度树在v435不存在该最后覆盖，不能按默认文件判断研究父版。
