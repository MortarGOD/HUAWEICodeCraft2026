# v376：同次校准K/V精确缓存

父版v375，原父AST完整前缀保持，仅增加校准/动态K/V包装。默认solution.py未替换。借鉴并复核仓库已有attention_factor_cal_cache.py，不把缓存当新量化算法。

## 边界

- 仅缓存最后三份校准样本的K/V，Tensor身份只作快速候选筛选，命中还须输入快照、dtype/device、维度及完整state递归逐值一致。
- 最多8项、64MiB Tensor payload；超限不缓存，Python元数据不包含在payload数值中。
- 输入/state/输出深拷贝，命中返回副本；调用方修改返回值不污染缓存。
- 使用threading.local隔离线程，嵌套校准使用独立缓存，finally清空本次并恢复前层上下文。
- 校准之外K/V直接调用父函数，无测试结果保存、跨测试角色依赖、文件访问。新增threading.local来自既有允许使用的threading模块，不增加外部依赖。

## 实测与验证

实际v375/v376七组0/4/14/24/34/47/49完整校准状态逐值相同；各组五份测试Q/K/V合计105个返回逐值相同。119项公开状态/返回格式检查通过，测试调用未修改缓存统计，结束时线程缓存为空。

七组合计25次K/V复用命中，每组3–4次，峰值Tensor payload均小于64MiB。输入/scale/state/维度/角色变化、返回值变更隔离、容量淘汰、超大项旁路、线程隔离、异常恢复外层上下文和测试阶段禁用缓存检查通过。官方接口6/6、格式22/22通过。

计时仅单轮配对且与校验有部分重叠，不稳定：有的组快、有的组慢，总体未证明提速；不能以命中次数外推节省秒数。复制和完整状态比较也有成本。此版为等结果性能探针，不承诺线上300秒或精度增长，不能列为已证优于v375。

还未全250题等价回归、未覆盖线上所有形状。历史父校准不稳定性没有因此修复，输出等价证据只覆盖此次实测。

证据：tools/test_kv_calibration_cache.py、docs/v376-equivalence.json；实现tools/attention_kv_calibration_cache.py与solution/solution_v376.py。

下一步不盲目扩大缓存容量，若线上无提速则回退包装；精度主线仍为原始/输出度量按校准选择及V误差优化，22500+需线上确认。
