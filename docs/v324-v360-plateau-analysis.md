# v324-v360线上平台期复盘

## 结论

平台期是真实的算法平台，而不是判分异常。v321的softmax不变K平移使线上从20208升至20643，v322的attention-weighted K原点与更充分Lloyd更新再升至20803；这两版改动覆盖普适Q/K误差。v324只做等输出性能整理，成为后续稳定父线。

v325-v360的大多数候选转向V最终输出风险、局部尺度/矩、旋转、稀疏特征路由或极少数头的状态选择。线上结果集中在20800-20810，说明这些分支要么被守门退回父状态，要么只影响少量头/少量题，要么在代理激活上重新分配误差而没有降低真实前向输出的共同误差。v341的20720进一步证明V条件矩可能直接伤害线上分布。

## 为什么本地会误导

当前50组bank含真实模型权重，但Attention激活是建模/投影数据，不是Qwen与DeepSeek的真实模型前向轨迹。它适合检查接口、性能和大结构收益，不足以可靠选择0.1%量级的门控：v358本地为正而线上20803，v360仅一个代理异常组净增0.267541，线上也只有20803.75。因此以后不再把单组、小数级增益当成精度发版证据。

## 新筛选

`probe_k_probe_coverage.py`把K平移使用的Query原型从最后两份校准集扩展为跨4/5份校准集的等预算原型。17/50组实际改变，说明代码路径有覆盖；但全bank结果分别为-0.056093、+0.026072、-0.138692，且正负集中在尾部少数组。简单扩大校准覆盖仍然只是误差交换，不生成v361。

进一步的`probe_k_probe_cv.py`在五份校准集上按KV head，从后两份、前两份、四份均衡、相邻两份四个等长原型中选择。它只让9/50组、11个head偏离父选择，测试总量反而-0.266660；损失主要集中于group47。现有校准代理连按头原型选择都不能可靠迁移，继续加阈值只会过拟合。

## 后续发版门槛

停止V风险代理、单组硬门控和只改变极少数头的阈值微调。下一个精度版本必须满足至少一项：覆盖多数已启用Q/K头的结构变化；在多个真实来源/长度分层上同向；或由真实线上消融能唯一支持。低于该标准的研究只记录，不消耗线上版本号。
