## 新方向

v322的attention-weighted K平移用校准Query估计当前Key各token的重要性。v361首次利用评测Q→K→V的顺序：Q接口在进程内缓存当前测试Query，K接口构造当前Query候选，并按KV head比较softmax分布后选择。它在本地250题中匹配85题、替换29个head，证明不是空路径；但代理总量-0.097239，完整回归235.46秒，相对同进程父线181.43秒过重，不建议提交。

v362删除第二次K量化与候选概率搜索，直接用当前测试Query替换原`kt_probe`，复用v324原有一次`_ts_quant`和原有head mask。校准阶段显式禁用缓存，Linear及Attention状态训练保持v324。Q路径复用父函数内部已经解码的原始Query，没有重复NVFP4解码。

该实现依赖同一Attention样本按Q、K、V顺序调用；若线上独立或并发调度角色，形状不匹配时会回退，但相同形状并发可能串样。本地与公开评估器均为顺序调用。它是对“校准Query到测试Query分布漂移”假设的直接大结构消融：若线上明显提升，后续继续做当前V最终输出感知；若仍约20803，则停止输入原型路线，转向Q/K联合量化目标。
