# v354：统一基线的共同候选选择探针

v354以v353为父，只修改共同变换/V核四种组合的选择规则。原规则按固定顺序逐次比较，每次要求相对当前最佳候选的两个Query折都改善1%；新规则让每个候选统一相对最初基线两折均改善1%，再在合格集合中选择两折平均最终Attention输出MSE最低者。候选、costs、查询、量化次数和阈值均不增加。

Linear、三角Gram恢复、V概率因子、校准缓存、动态量化和state结构均保持v353。没有合入跨序列辅助或全Query实验。

## 验证

- 直接提取生成选择块完成6000项随机检查：非基线候选均满足相对原始基线两折1%改善，所选候选平均校准MSE不高于原贪心结果。
- 实际v354相对v353，除模块说明外仅一个共同候选校准函数AST变化；禁止模块/动态I/O扫描由check_v354覆盖。
- 官方self_check接口6/6、格式22/22通过。
- 两bank各6组、合计60例实际文件配对：feedback组0改变选择并有−0.000040177原始分数和差，其余55例同分；总增量−0.000040177。27项结构/状态检查通过，无JOINT错误。
- 单轮校准合计v353/v354为26.92/24.04秒，但v353首组6.75秒是明显冷启动；去除首组约20.17/20.02秒。不能把这次波动宣称为算法加速，因为规则本身没有新增量化计算，完整线上耗时未测。

## 决策

本地结果不支持把v354列为首选，但只有一个组发生极小变化，不能100%断言线上劣化。根据用户要求保留为可提交线上探针并推送，提交优先级低于v353。线上参考仍锚定v324约20803/246秒；不预测+50或22000，不保证300秒。默认入口和Linear未覆盖。
