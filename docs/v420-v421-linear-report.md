## 迁移条件与实现

来源为本地 test/base_1.7 固定提交 `52b490459d117c7982d2ed7d14cbe791a756c193`，初始候选复用及前缀搜索的源码依据见 `docs/test参考实现优化分析-20260907.md`。先核对当前方案再找差异：父版已有真实输出目标、多尺度候选和 64/4 通道搜索，所以本轮没有把这些已有能力重新列作新算法。

v420 只改 `_quantize_linear_exact_target` 初始候选区域。每中心执行与原量化器完全相同的 float32 转换、reshape、amax、除 7、编码，后续通过已有 prepared 参数读取；候选的 offset 和 threshold 仍各自求解。机制样例的 24 次峰值编码降为 2 次；不同阈值的误差没有混用。实际中心通常已经 FP32；对直接传 BF16 的辅助调用，prepared 会延长一份 FP32 临时副本的生命周期。

v421 校准时先完整运行父版，在返回之后才加标记并保存原始 NVFP4 解码 W 的 BF16 副本。该解码本来就是 BF16，保存不引入额外舍入；父权重和既有 state 不变。必须已有完整 Gram，且 I≤4096、O≤8192、非 direct_output；实际父版最终包装器会为符合 O≥2I 的 up-projection 建立 Gram。额外持久状态为 2OI 字节，上限 64 MiB，本地最大启用层为 4 MiB。

动态仅二维输入、行数≤128启用，一轮、每行最多 8 个坐标、每码最多±2，保持 scale_factor/lv2/lv3。令 r=AWᵀ−ZBᵀ、g=rB、G=BᵀB，按单坐标 `−2g_jδ_j+G_jjδ_j²` 排序；每个排序前缀用 `−2gᵀδ+δᵀGδ` 算全交叉项，可同时改变不同 64 通道块。没有重建大 Gram 或 rows×k×outputs 临时张量，也不称穷尽组合。

FP32 预测只产生候选；最终以与当前评测器一致的合法 BF16 解码、**完整行数**的 BF16 GEMM，对原始 A.float()@W.float().T 逐行严格下降才采用。打平、拒绝、不满足门控均保留父结果。初稿曾裁剪到预测有益行计算 GEMM，审查发现行数可能改变后端数值路径，已在正式 hash 中改为全行验收；非二维输入直接回父。未在校准内部触发新增搜索。

## 推送后本地结果

当前本地评分实际是：原始 NVFP4 参考 FP32 GEMM，Algorithm1 基准量化器强制产生 FP32 参数并做 FP32 GEMM，选手合法参数 BF16 解码并做 BF16 GEMM，然后算 FP32 MSE。最初验证脚本误判基准 dtype，首个断言即失败、没有产生估计结论；[初始失败记录](v420-v421-harness-initial-failure.json)保留，已按 `hif4_quant.py` 实际运行修正，未修改评测器。
