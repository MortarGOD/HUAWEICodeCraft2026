# Option 8：守门样本退化 —— 本地/线上迁移失效的统一根因（2026-09-10，goal round 8）

## 1. 统一根因

两套子系统的校准判决**都用「最后一个校准样本」当守门样本**：

- attention：`hold = calib_qkv_list[-1]`（`solution_v435.py:3139`）
- linear：`_linear_refine_fixed_decoder` 里 `calibration[-1]` 既是 `<2` 的判据也是打分样本
  （`solution_v435.py:1949` 与 `:1980`）

而**官方样例的校准列表把退化样本放在最后**，我们的镜像库却放在最前或干脆没有：

| | 官方 `mini_sample` | 我们的 structural-v3 镜像 |
|---|---|---|
| attention 校准 token 列表 | `[10,128,512,1024,1]` —— **末位 T=1** | 50/50 组**完全没有 T=1** |
| linear 校准激活行数 | `[10,128,512,1024,1]` —— **末位 1 行** | `[1,10,128,512,1024]` —— **1 行在最前** |

**T=1 时 softmax 恒为 1、attention 输出恒等于 V，Q/K 在数学上不可能影响输出**；
1 行激活的线性守门同样几乎没有信息量。

于是：**在官方/判题器的排布下，每一个守门判决都在一个退化样本上评估，机制静默返回父版；
而在我们的镜像库上同一个机制火力全开。** 这就是「attention 本地→线上迁移率实测约 0.02」
与 openaddr 独立测得 0.22 之间差距的最可能来源，也是 v491（本地 +204 → 线上 −34）、
v501（本地 +215 → 线上 −78）、v521（本地 +398 → 线上 +9）这一串方向/幅度双错的统一解释。

## 2. 两个已实测的修复

### attention：旋转恒开（v625）

守门用严格小于，而 T=1 上「旋转」与「不旋转」的 loss **逐位相同**（5.065478e-03），
于是 `rot` 永远停在 0。逐样本实测其余 4 例（T=10/128/512/1024）**全部**判旋转更好。

| 官方 mini_sample attention | mean | 250 题折算 |
|---|---|---|
| v435（rot=0） | 0.154586 | 3864.7 |
| v625（rot=1） | **0.358589** | **8964.7（+5100）** |

### linear：守门改用非退化的末位样本（v626）

`if not calibration or int(calibration[-1][0].shape[0]) < 2: return parent`
在官方样例上（末位 1 行）**整体跳过精化**，直接返回父版。

| 官方 mini_sample linear | mean | 50 题折算 |
|---|---|---|
| v435（守门用末位 1 行） | 0.382698 | 1913.5 |
| v626（守门用末位非退化样本） | **0.423636** | **2118.2（+204.7）** |

且该路径正是**宽 M>K 区间**：官方线性组是 8192×2048，而 full-gram 分支的条件是
`teacher.shape[0] >= 2 * teacher.shape[1]`（`:1991`）—— 与「Linear 剩余池 +1232 全在 M>K 宽组」
的已知瓶颈完全重合。

两个修复都只在**原本守门退化的数据**上生效：在镜像库上 v625 只改到少数原本放弃旋转的
group（+29.7 折算），v626 是严格 no-op。

## 3. 退化守门**没有**解释的部分

把 `T<=1` 从 attention 校准列表过滤掉（拟合与守门都改用非退化样本）后，官方样例得分
0.358589，state 键与 v625 **完全相同**（`q/k_state` 仍只有 `kvh/rot/rseed`，
`v_state` 仍只有 `v435_content_parent`）。即退化守门**只**杀掉了旋转；QKS 平滑、Q/K GPTQ、
联合变换、温度、VM/VR 换成非退化守门后**依然被拒**。round 6「拟合型机制在官方数据上
确实没有可重复结构」的结论成立，与 v624（强制 Q/K GPTQ → −0.0455）一致。

## 4. 镜像库的构造缺陷（必须修）

我们的镜像库**从不复现官方排布的退化末位样本**：

- attention：50/50 组没有 T=1，所以从未测到「守门退化」这条路径；
- linear：1 行激活在最前，所以末位守门永远是 1024 行。

**后果**：过去所有「机制在本地有效」的结论，都是在一条判题器不会走的代码路径上得到的。
后续任何镜像库都必须显式包含
`attention calib = [.., T=1]`（T=1 在末位）与 `linear calib rows = [.., 1]`（1 行在末位）
这两种排布，否则守门判决继续被误测。

### 8 个 V/QK 站点为什么「不可达」

它们有一个**共同的上游总闸**：

```
3696: if len(calib_qkv_list) < 2 or not states["q_state"].get("gq") or not states["k_state"].get("gq"): return states
3865: if (len(calib_qkv_list)<2 or head_dim%64 or not states["q_state"].get("gq")): return states
3897: if len(samples)<2 or d%64 or not states['q_state'].get('gq'): return states
4163: if d%64 or not parent['q_state'].get('gq'): return parent
4279: if len(samples)<3 or d%64 or not parent['k_state'].get('gq') or 'u' not in parent['k_state']: return parent
4529: if len(calib_qkv_list)<3 or d%64 or not all(parent[r+'_state'].get('gq') for r in 'qk'): return parent
4602: if len(samples)<2 or d%64 or not parent['q_state'].get('gq') or not 4<=len(samples[-1]['v'][0])<=4096: return parent
```

即整个 attention 拟合栈（JOINT / TEMP / VM / VR / KT / TS / OJ / LT / a430）**都挂在
`gq`（Q/K GPTQ）这一个判决之下**。官方样例上 `gq` 未通过，所以这些站点在读到
`samples[-1]` 之前就已经 `return parent` —— **末位的 T=1 对它们根本不是约束**。

这也解释了 round 8 的实测：把 `T<=1` 从校准列表过滤掉后 state 键**完全不变**，
即退化守门只杀掉了旋转，拟合栈另有原因被拒。

`gq` 的拒绝依据是 `QKS_DEBUG.stab = 0.0597`（跨校准样本的通道结构相关性，
统计量本身就在非退化的 4 个样本上算），属**统计型真实拒绝**；
强制打开它（v624）在官方样例上得 **−0.0455**，即守门判对了。

### 潜在风险（今日无可测收益，记录备查）

那 8 个站点的 `4 <= rows <= 4096` 是**潜伏的同类 bug**：一旦 `gq` 在某批数据上被接受，
而该数据的末位校准样本 T<4，这些机制会被错误地整体关闭。今天测不到收益（`gq` 先挡住），
所以不单独出版本；重启条件 = 任一版回执显示 `gq` 在判题器上被接受。

## 7. 纯 V 题（T=1）的池子已满（round 9，负结果）

官方 token 列表把 **T=1 放在测试集末位**，而 T=1 时 attention 输出恒等于 V：
**这类题目的得分只由 V 决定，Q/K 在数学上不可能影响**。若判题器沿用同一排布，
则约 1/5 的 attention 题是纯 V 题 —— 一个合法且不需要对端的池子。

实测（`tools/probe_v_ceiling.py`，官方 5 例，S1P2 格点上 ±3 个码步的逐元素最优）：

| case | T | 标准 HiF4 MSE | 我们 V 的 MSE | oracle MSE | 当前 score | oracle score |
|---|---|---|---|---|---|---|
| 0 | 10 | 5.42271e-03 | 4.79011e-03 | 4.07425e-03 | 0.116658 | 0.248669 |
| 1 | 128 | 5.24263e-03 | 4.41259e-03 | 4.00316e-03 | 0.158326 | 0.236420 |
| 2 | 512 | 4.92543e-03 | 4.15154e-03 | 3.80097e-03 | 0.157121 | 0.228297 |
| 3 | 1024 | 5.04087e-03 | 4.27597e-03 | 3.89312e-03 | 0.151741 | 0.227690 |
| **4** | **1** | 9.05700e-03 | 7.49351e-03 | **7.49351e-03** | 0.172628 | **0.172628** |

**T=1 这一例上 oracle 的改善恰好是 0**（两个 MSE 逐位相同）：我们的 V 编码器已经落在
逐元素 S1P2 格点最优上。所以纯 V 题的余量是 **0**，V 侧没有可拿的分；
T>1 的用例在恒等度量下还有 oracle 余量，但 T>1 的输出度量是 `||P(V̂−V)||²`（需要对端），
恒等 oracle 不是有效上界，故不作结论。

## 8. 重大修正：判题器很可能是 V 主导，openaddr 的 Q/K 71–85% 与回执不符（round 11）

v625 回执 Δ=0 证明**判题器不是**我们这份 `mini_sample` 的退化排布。既然那份文件不代表判题器，
就必须另找一个与线上一致的 attention 库。`docs/papers/hif4-public-references/test/datasets/`
下的第三方库 `qwen2_5_14b_online_profiled_v2` 是目前最好的候选。

**角色预算（`tools/probe_attention_role_budget.py`，v435）：**

| 库 | 组数 | player 聚合 score | V 端占比 | **Q/K 端占比** |
|---|---|---|---|---|
| `qwen2_5_14b_online_profiled_v2`（全库） | 50 | 0.584123 | **66.1%** | **33.9%** |
| `qwen2_5_14b_online_profiled_v2`（前 5 组） | 5 | 0.674328 | 81.4% | 18.6% |
| structural-v3 镜像（我们） | 50 | — | 87.0% | 13.0% |
| mini_sample（我们这份残缺件） | 1 | — | 12.8% | 87.2% |

**先纠正一个我自己的误判**：`online_profiled_v2` **前 5 组**的 attention 折算 16858.2 与
「线上 attention = 21304 − 4450 = 16854」只差 4 分，我一度以为找到了线上分布。
全库 50 组是 0.610325 → **15258**，所以那个吻合是**5 组小样本的巧合**，不构成证据。
教训与 round 8 的 `public_quantizer`、round 11 的 `mini_sample` 同类：小库/残缺库上的吻合不得当结论。

**去掉巧合后仍然成立、而且与之前路线相反的部分：**

- 在我们手上**唯一**显示 Q/K 主导的是那份残缺 `mini_sample`（87.2%）——它刚被回执证伪为代表；
- `online_profiled_v2`（第三方、按线上刻画）与我们的镜像都是 **V 主导**（66.1% / 87.0%）；
- 因此 **openaddr 的「判题器 Q/K 占 71–85%」与现有全部本地证据冲突**，
  round 6–7 据此把注意力工作转向 Q/K 侧的前提应当撤回；目标裁决 (2) 的技术路线需要按回执重新校准。

**V 侧是合法且主导的池子**（`online_profiled_v2` 全库，聚合口径）：

```
player 误差 / baseline        = 41.6%
  其中 V 端贡献               = 27.5%   ← 合法可攻（V 不需要对端，校准数据为真）
  其中 Q/K 端贡献（V 精确时）  = 14.1%   ← 受假对端协议限制
若 V 理想 → score 0.859（现在 0.584）→ V 侧池子约 +0.275（250 题约 +6875 的上界）
```

即：**注意力侧可攻的余量主要在 V，而 V 恰好是不需要对端的那一侧。**
round 6–11 期间我把 V 侧判为「已饱和」，依据是**残缺 mini_sample 上 T=1 用例的格点最优**；
该依据随同一证伪失效，V 侧需要在这个新库上重测。
