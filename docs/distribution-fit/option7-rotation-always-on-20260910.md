# Option 7：官方口径上整条 attention 栈其实是关的，强制打开旋转（2026-09-10，goal round 8）

## 1. 修正 round 6 的记录：旋转也没开

round 6 记录「官方样例上部署路径退化为一次 Hadamard 旋转 + 基础量化器」。实测 state 的值：

```
mini_sample（官方）  q_state = {'rot': 0, 'rseed': 0, 'kvh': 2}
                     k_state = {'rot': 0, 'rseed': 0, 'kvh': 2}
                     v_state = {'v435_content_parent': None}
结构镜像库           q_state = {'rot': 1, 'rseed': 0, 'kvh': 2, 'qs': …, 'gq': 1,
                                'u': …, 'rf': 1, 'H': …, 'temperature_gain': …}
                     k_state = {'rot': 1, 'rseed': 0, 'kvh': 2, 'ks': …, 'gq': 1,
                                'u': …, 'rf': 1, 'H': …}
```

`v_state` 的 `v435_content_parent` 是 `None`，`hif4_dynamic_quantize_v` 因此直接走父版
`_v435_parent_dynamic(..., None)`。所以官方样例上**部署路径是「无 state 的基础动态量化器」**，
连旋转都没有。round 6 的「旋转 + 基础量化器」说法把旋转算进去了，实际旋转是 0。

## 2. `rot = 0` 是怎么来的

```python
ATTN_ROTATION_CANDIDATES = 1
...
loss_off = run_rot(q_rot, k_rot)
rot = 0
rseed = 0
if R is not None:
    best_loss = loss_off                    # ← 未旋转作为「擂主」
    best_R = R
    for seed_index in range(ATTN_ROTATION_CANDIDATES):
        ...
        if loss_on < best_loss: rot = 1     # ← 只有严格更优才旋转
```

即：**「不旋转」是一个默认擂主**，旋转必须在内部代理 `run_rot` 上严格胜过它才会被采用。
在官方样例上它没有胜出，于是 `rot = 0`。

这也解释了 round 6 里 v621/v622/v623（候选数 8/16/64）为何增量**恰好 0.00000**：
候选再多，全都输给擂主，`rot` 始终是 0。

## 3. 决定性测量：内部代理在它自己的数据上是反的

强制打开旋转（`rot=1, rseed=0`，其余不动），在官方样例上：

| 口径 | 现状（rot=0） | 强制 rot=1 | Δ |
|---|---|---|---|
| **官方 mini_sample 测试集（5 例）** | 0.154586 | **0.358589** | **+0.204004** |
| 官方样例自身的校准集（5 例） | 0.126100 | **0.278669** | +0.152569 |
| 折算 250 题 attention 分 | 3864.7 | **8964.7** | +5100 |

- 旋转在**校准集上也更好**（0.2787 vs 0.1261），可是部署用的内部代理 `run_rot`
  判它更差 —— 代理与被打分的量在**同一批数据**上就相反。
- `random-orth` / `dct` 两个替换 `_make_R` 的变体增量恰好 0，正是因为它们的 `rot` 仍是 0，
  与上面的判断一致（也说明 `_make_R` 打桩有效）。
- 逐位验证：`tools/probe_qk_geometry.py`，`load_solution` 每次新建模块、不打桩残留，
  且 `rot=0` 与 `rot=1` 的 state 值已单独打印确认。

## 4. 为什么这是合法且可迁移的

- `(q R)(k R)ᵀ = q kᵀ`：旋转严格保持 logits，只改变量化几何。
- R 是**固定**的 Hadamard×符号矩阵（seed 0），不依赖任何校准结构；两个角色各自从自己的
  state 里取 R，不需要跨角色缓存、调用顺序或可变全局状态。
- 属于 openaddr 定理里「**结构不可知机制**」那一类 —— 恰恰是唯一被证明会迁移的一类。
  与 v501/v521 那类「校准拟合型」（同一批机制本地 +1841/+398、线上 −78/+9）性质不同。

## 5. 候选 v625

`v625 = v435 + 旋转恒开`（`tools/build_patch_version.py --spec docs/patches/v625.json`）。
单机制、无新增全局量、父版 hash 已断言。

- **校准开销不变**：候选损失 `loss_on` 本来就每轮都算，改的只是判决。
- **动态开销**：只在原本 `rot=0` 的数据上多一次 `(T, nh, d) @ (d, d)` 矩阵乘。
  干净无争用的计时（镜像库 250 例，单独运行）：**v435 = 144.3 秒，v625 = 140.9 秒** ——
  没有测到开销上升。此前一次 171.6→195.8 秒的 +24 秒是并发评测造成的争用噪声，
  与 round 8 早些时候记录的「并发会把 4 线程计时抬高约 2 倍」一致。
- 因此这是一个「只在代理拒绝旋转的数据上生效」的改动：我们唯一能测到的这类数据
  （官方样例）上，被打分的量偏好旋转 +0.204。

## 8. 根因：守门样本是 T=1（round 8 追加）

`hold = calib_qkv_list[-1]`，而官方样例的 token 列表是 `[10,128,512,1024,1]` ——
**最后一个校准样本 T=1**。T=1 时 softmax 恒为 1、输出恒等于 V，**Q/K 在数学上不可能影响输出**。

逐样本实测（用代码自己的 `run_rot` 口径，含量化 V）：

| 校准样本 | T | 不旋转 loss | 旋转 loss | 胜者 |
|---|---|---|---|---|
| 0 | 10 | 2.309853e-02 | 2.294241e-02 | 旋转 |
| 1 | 128 | 3.009758e-02 | 2.396001e-02 | 旋转 |
| 2 | 512 | 3.994742e-02 | 2.602802e-02 | 旋转 |
| 3 | 1024 | 4.198702e-02 | 2.588902e-02 | 旋转 |
| **4** | **1** | **5.065478e-03** | **5.065478e-03** | **平局（逐位相同）** |
| 5 例均值 | | 2.803921e-02 | 2.077699e-02 | 旋转 |

守门用严格小于 `loss_on < best_loss`，T=1 上两者**恰好相等**，于是 `rot` 永远停在 0。
测试集同样是 `[10,128,512,1024,1]`，且 4/5 例都判旋转更好。

**这是「守门样本退化」而不是「代理口径错误」**：同一批数据换成非退化样本后旋转大胜。
即 v625 的 +0.204 不是强制出来的特例，而是修复了一个退化判决。

### 只解锁了旋转

把 `T<=1` 的样本从校准列表里过滤掉（拟合与守门都改用非退化样本）后，官方样例得分
**0.358589**，state 键与 v625 **完全相同**（`q/k_state` 仍只有 `kvh/rot/rseed`，
`v_state` 仍只有 `v435_content_parent`）。即：

- 退化的守门样本**只**杀掉了旋转；
- 其余拟合型机制（QKS 平滑、Q/K GPTQ、联合变换、温度、VM/VR）在换成非退化守门后
  **依然被拒** —— round 6「拟合型在官方数据上确实没有可重复结构」的结论成立，
  与 v624（强制 Q/K GPTQ → −0.0455）一致。

### 顺带修正 round 6 的「规范自由度已穷尽」

round 6 记「旋转候选 8/16/64 增量恰好 0，seed 0 在 64 个候选里最优」。
实测 64 个 seed 的 loss **逐位完全相同**（mean 2.357484e-02，最优=最差=seed 0，0/64 更优）。
原因是 `_make_R` 返回 `H · diag(±1)`，而 HiF4 编码有**独立符号位**、共享尺度只含幅度，
符号翻转对量化误差**在构造上不可见**。所以正确说法是「64 个候选量化等价」，
而不是「seed 0 恰好最优」。

### 基的选择没有系统性作用（负结果）

旋转强制打开后比较固定正交基（官方 5 例）：

| 基 | mean | 折算 250 题 |
|---|---|---|
| Hadamard（现部署） | 0.358589 | 8965 |
| DCT-II | 0.362085 | 9052 |
| 10 个随机正交 | 均值 0.359616，std **0.023955**，min 0.330367，max 0.411664 | — |

随机正交只有 **4/10** 优于 Hadamard，且离散度（±0.024）远大于均值差（+0.001）。
**此前单次测到的 random-orth +0.0113 是 5 例小库上的噪声**，不构成机制。
基这条线到此关闭：v625 的 Hadamard seed 0 就是合适的形式，不再做后续候选。

### 旋转之后残差仍在 Q/K

官方样例（旋转恒开）的角色预算：**V 18.5% / Q/K 81.5%**，
与 openaddr 独立测得的判题器 71–85% 一致。即旋转拿回了一部分 Q/K 池
（按例均值 score 0.1546 → 0.3586），但 Q/K 仍是主要残差，而其合法杠杆在
round 6/7 已穷尽（需要动态接口拿不到的对端信息）。
