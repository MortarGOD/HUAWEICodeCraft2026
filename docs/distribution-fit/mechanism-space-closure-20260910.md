# 合法机制空间闭合审计（2026-09-10，goal round 18）

## 0. 目的

经过 round 11（v625 Δ=0）、round 17（v628 −8987）两次线上裁决，注意力侧只剩否证记录。
本轮不再提新机制，而是把**六 API 契约下所有可用的自由度逐条列出**，附本地实测与线上回执，
使「已穷尽」成为可核对的结论而不是断言；同时写明**重新开启的具体条件**。

## 1. 契约允许我们选择什么

- **六个 API**（`hif4_calibration_and_quantize_weight` / `hif4_dynamic_quantize_activation` /
  `hif4_calibration_attention` / `hif4_dynamic_quantize_q/k/v`）；Linear 校准只能返回
  `{weight_params, activation_state}`，Attention 校准只能返回 `{q_state, k_state, v_state}`。
- state 只能是纯数据（None/bool/int/float/str/CPU 张量/其容器）。
- 动态调用**只看当前角色的输入与该角色自己的 state**：不得跨角色共享缓存、依赖调用顺序、
  依赖可变全局状态。
- 单文件、无文件读写、无环境探测、确定性。
- 每个角色我们能决定的只有两件事：
  1. **量化前的变换**（Q/K 若要保 logits 必须成对：`A_q A_kᵀ = I`，即同一个正交变换；
     V 因为直接进入输出，不能单独变换）；
  2. **码字/尺度选择**（每 64 元素共享的 E6M2 尺度、每 8/16 元素的 E1 微指数、S1P2 尾数）。

| logits 目标下的码搜索 | oracle 余量 **90–97%**（`probe_logits_vs_mse`，正向/转置一致 5e-8） | — | **需要真实对端，不合法** |

**Q/K 池子仍很大**：在 `qwen2_5_14b_online_profiled_v2` 全库 250 例上把 Q、K 换成精确张量，
score 0.610325 → **0.747931**，即**池子约 +3440**。但它只能靠对端信息拿到。

**合法的（无对端）目标只有「各自的重建误差」**，而该目标已到顶（上表前两行）。
理论上也一致：若对端先验各向同性，`E‖Q̂K̂ᵀ−QKᵀ‖² = σ²‖Q−Q̂‖² + σ_e²‖Q̂‖²`，
logits 目标**退化回逐张量 MSE**——所以 logits 余量全部落在各向异性（即不可观测）的那部分上。

### 本轮的一个自我纠错

我写过一个 `probe_qk_ceiling.py`，用「把 Q/K 的码往 `raw['q']` 移动」来测恒等 oracle，
得到 −30 / −39 / −90 的荒谬值。**该工具是错的，已删除**：`play['q']` 在**旋转后的坐标系**
（旋转使 `(QR)(KR)ᵀ = QKᵀ`），而 `raw['q']` 没有旋转，两者不同基，朝它移动等于破坏张量。
V 侧没有这个坐标系问题，所以 round 12–17 的 V 测量口径有效；Q/K 侧必须用「换成精确张量」
这种坐标系无关的口径（上表的 +3440）。

## 3. V 侧

| 杠杆 | 本地实测 | 线上回执 | 状态 |
|---|---|---|---|
| 基础量化 + 自内容精化 | 比标准 HiF4 好 **+2118**；恒等度量 oracle 只多 **+147** | v501 −74 / v521 +9 | **到顶** |
| 评分度量（`P` 加权）目标 | oracle **+1323 ~ +4482**（9/9 库为正） | — | **需要 `P`（即 Q/K），不合法** |
| 无对端代理 `I+λ·11ᵀ` | 全库：镜像 +1874、online_profiled_v2 +1508、public_quantizer −106 | **v628 −8987** | **证伪并冻结** |

代理失效的直接原因是**量纲错配**：秩一项随 T 增长，固定 λ 下每元素移动随 T 线性增大而饱和到
±3 码步钳位（T≥128 时几乎每个元素都被推到钳位，0.75·unit = 码幅的 43%），
即**近乎整体重编码 V**。Dirichlet 推导要求的平衡尺度是 **λ = κ/T（κ=O(1)）**，T=512 时 ≈0.002，
比使用的 0.05/0.1 小 25~50 倍。但把 λ 缩到 0.002 后损害与收益同比例缩小：
**强到有用即灾难（−8987），安全到不伤即等同不做（±100 内）**。

反过来，v628 的巨额负值**证实判题器的 V 度量接近恒等**（注意力尖峰 ⇒ `PᵀP` 近似对角），
即我们原来的 V 目标本来就是对的。


## 6. 重新开启的条件（具体、可检验）

任一条成立即可重启对应线路：

1. **判题器 V 度量确实偏离恒等**：例如某个只改 V、方向已知的探针给出明确正回执；
   或拿到判题器的注意力稀疏度/熵的独立测量。
2. **校准期对端为真**：若有证据表明 `hif4_calibration_attention` 的 Q/K 在 V 校准中是真实的
   （而非假对端），则 Q/K 拟合型机制重新变为合法，且可在真实 `P` 上选 λ。
3. **判题器形态信息**：attention 的 T / 头数 / MHA-GQA 分布，用于判断哪些 group 值得投入
   （目前完全未知，只能靠回执）。
4. **新的数学构造**：一类**不需要对端**、且能在保 logits 的前提下改变量化几何的 Q/K 机制。
   现有全部候选（正交变换、逐通道缩放、置换、微指数分组）要么已穷尽，要么需要数据依赖的
   成对约定，而后者在角色独立 state 与假对端协议下不合法。

## 8. 重要更正（round 20）：保 logits 的变换族不止正交，还有一个未穷尽的对角族

§2 我写「Q/K 若要保 logits 必须成对：`A_q A_kᵀ = I`，即同一个正交变换」——**这是错的**。
条件 `A_q A_kᵀ = I` 只要求 `A_k = A_q^{-T}`，即 **`A_q` 可以是任意可逆矩阵**，
正交只是其中一个子族。我们一直只在这个子族里搜索（Hadamard/DCT/随机正交），
**把整个对角子族（SmoothQuant 型）漏掉了**：

```
q ← q·s ,  k ← k/s      ⇒  (q·s)·(k/s) = Σ_d q_d s_d k_d / s_d = q·k   （逐元素成立）
```

即**精确保持 logits**，与正交变换并列的合法杠杆，而且**不是旋转的等价类**（对角缩放不可约化为正交）。

### 为什么此前没发现

- **在我们镜像上它是 no-op**：镜像的 `q_state` 一直带着 `qs`（`['H','gq','qs','rf','rot',
  'temperature_gain','u']`），平滑本来就是开着的，所以镜像永远测不出差别；
- **在官方样例上它被守门拒绝**（`QKS_DEBUG.stab = 0.0597 < QKS_STAB_MIN = 0.5`），
  `q_state` 只有 `['rot']`，所以官方样例上它是关着的。
- 于是「开着的库」和「关着的库」我们各有一个，却从未把两者对齐比较过。

### 实测（强制只接受 QKS 平滑，其余守门保持诚实）

| 库 | v637 | **v639（只放行 QKS）** |
|---|---|---|
| 官方样例 attention | 0.154586 | **0.247073（+2312 / 250 题）** |
| `online_profiled_v2` | 0.610325 | **0.631833（+538）** |
| 我们镜像 | 0.789440 | **0.789440（no-op，本来就开）** |

对照：**只强制 `gq`（GPTQ）在官方样例上是 −1139**，四门全开是 +1801（= v638）。
所以「有害的是 GPTQ，有益的是平滑」，而平滑恰是唯一**坏情况有界**的那个
（它不可能改动 logits，只能改变量化几何）。

### 对「已穷尽」结论的影响

Q/K 的合法杠杆**并未穷尽**——对角族此前完全没被搜索过。这也修正了 round 18 闭合审计的结论：
应当把「可逆对角变换族」列入待探索空间。这条线的恢复条件相应放宽：
**只要判题器的 Q/K 平滑被拒绝，v639 就是一次有界的、机制明确的下注。**

## 9. 重要更正（round 27）：假对端协议被线上分数否证，Q/K 拟合**不是**被封死，而是**已饱和**

### 9.1 协议模拟（`tools/probe_judge_protocol.py`）

按 AGENTS.md 记录的判题器协议（三次调用、各次仅目标角色为真、只保留对应 state）做忠实模拟：
把非目标角色的**时间轴逐样本置换**（形状不变、边缘分布不变、只破坏角色间逐行对应）。

| 版本 | 单次全真校准（我们一直的口径） | **模拟判题器协议** |
|---|---|---|
| v637 | 0.555781 / 0.610325 | **−4.661593 / −5.636145** |
| v642 | 0.678008 / 0.678131 | **−4.383427 / −5.395438** |

（两个数字分别是 online_v1 / online_profiled_v2 全库 250 例。）

诊断：该协议下 **state 键完全相同**（`['H','gq','rot','temperature_gain','u']`，
即守门照旧全部接受），但 `u`/`H` 是**对置换数据拟合出来的**，动态路径照用 ⇒ 输出崩溃。

### 9.2 由此得到的推断

**线上 attention 是 +0.674（21327 的一部分），不是 −4.7。** 所以判题器上不可能在跑这种
「逐样本置换的假对端」——否则分数会崩到负几千。

⇒ **判题器的校准提供的是结构一致的（实质真实的）对端**，其拟合机械**是功能正常的**。

**因此 round 18 闭合审计里那条「假对端协议封死 Q/K 拟合」的理由不成立，应予撤回。**
（该条也是 AGENTS.md 的工作假设；本轮的模拟+线上分数显示它至少不能按最严形式理解。）

### 9.3 但 Q/K 仍然拿不到分：不是被封死，而是**已饱和**

既然拟合是合法且功能正常的，我把它当作可用杠杆重新测了一遍：

| 版本/机制 | 尖峰库结果 | 线上回执 |
|---|---|---|
| v504（Q/K 精化 sweep 1→2） | online_v1 **−43**、online_profiled_v2 **+12** | 未提交 |
| v501（H 改 fp32 承载） | — | **−74** |
| v521（VK queries ×8 + 门限放宽） | — | **+9** |
| v639（强制打开 Q/K 平滑） | — | **≈0** |
| 强制 gq（GPTQ）单独 | 官方样例 **−1139** | 未提交 |

即：**Q/K 的 GPTQ + 平滑 + 逐头精化这一整套是开着的、拟合是有效的，但把其中任何一项调强或调弱
都基本不动分数**（都在 ±100 噪声带内）。⇒ Q/K 侧的问题不是"拿不到对端"，而是
**现有机制的效力已经饱和**，需要的是**不同种类**的机制，而不是同一族调参。

### 9.4 对当前候选的影响

v642/v651 属于**无拟合 state**的机制（只依赖当前 V 与精确 V 输入），因此**不受协议形式影响** ——
这一点在本轮得到加强：它们的增益不依赖对端是否真实，只依赖判题器的 V 度量是否接近恒等，
而后者有 v628 的机制级证据。
