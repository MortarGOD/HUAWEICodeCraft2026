# 接口级闭合：为什么 23000 在六 API 契约下不可达（2026-09-10，goal round 33）

## 0. 结论

**在六 API 契约与固定 HiF4 布局下，我已经找不到把线上总分从 21327 推到 23000（甚至 22000）的
合法机制。原因是结构性的，不是"还没调够旋钮"。** 下面把证据与推理完整写出，并写明重新开启的条件。

## 1. 攻击面在哪里（角色预算，T 真实的库）

| 库 | T 中位/最大 | V 端 | **Q/K 端** |
|---|---|---|---|
| `public_quantizer` | 512 / 1024 | 78.1% | 21.9% |
| structural-v3 镜像 | — / 2048 | 79.4% | 20.6% |
| **mini_sample（官方，判题方提供）** | 128 / 1024 | 12.8% | **87.2%** |
| v419_mini_sample | 128 / 1024 | 12.8% | **87.2%** |
| v1 | 19 / 45 | 9.0% | **91.0%** |

官方样例的角色占比**对 state 不敏感**：把机制强行打开后仍是 V14.5/QK85.5（v639）、V14.0/QK86.0（v635）。
且 openaddr **独立**测得判题器 Q/K 占 71–85%。⇒ **残差的 ~86% 在 Q/K，V 只占 13–14%。**

## 2. Q/K 可减的部分在哪里，以及为什么拿不到

`tools/probe_logits_vs_mse.py` 用「按 logits 目标重选 Q/K 码字」测出：
**logits MSE 的可达余量 90–97%**（自检：正向/转置目标一致性 5e-8；
修掉了三个实现错误：转置坐标系、GQA 联动、`kd[:kh]` 切片）。

**但那个 oracle 用的是「测试用例自己的对端码字与真实 logits 目标」。**
换成可实现的编码器时，Q 的编码规则只能是「q 自身 + 静态 state」的函数——它**看不到实例级的 K**。
在「对端先验各向同性」下，logits 目标**退化回逐张量 MSE**：

```
E_k || q̂ k̂ᵀ − q kᵀ ||²  =  σ² || q − q̂ ||²  +  σ_e² || q̂ ||²
```

也就是说：**可减的那 90–97% 全部落在「各向异性 / 跨 token 耦合」那一部分，
而那一部分恰恰需要实例级对端**。动态接口按角色独立调用、禁止跨角色缓存与调用顺序依赖，
所以它拿不到。

**能被静态 state 捕获的那部分**（对端通道 Gram ⇒ GPTQ）**已经在用，且已饱和**：

| 机制（在**正确库**官方样例上复测） | 结果 |
|---|---|
| v504 逐头精化 sweep 1→2 | **逐位相同**（不动点） |
| v624 只强制 gq/GPTQ | **−1139（有害）** |
| v639 只强制 QKS 平滑 | +2312（唯一有效，但线上本来就开着 ⇒ v639 回执 ≈0） |
| v635 强制整套 | +1801 |
| v654 v635 + 放宽 JOINT 门 1%→0.1% | **逐位相同** |

## 3. 其他两侧

- **V（只占 13–14%）**：编码已在**合法恒等最优**——尾数全 8 级、符号位、块尺度网格（合法加宽 ≈0）、
  微指数（`_quant_chunk` 对每个 sf 候选精确选 lv 树）四条维度逐条验证到顶。
  度量侧需要 `P`（即 Q/K），拿不到；v628 的 −8987 证明朝秩一方向走有害。
- **Linear**：上限 +550（4450→5000），而实测杠杆只有 **+23**（H=4 在官方宽组值 +747、线上只值 +23
  ⇒ 宽组仅占约 3%）。`_LINEAR_JOINT_ROUNDS` 4/8/12 轮得分完全相同（已收敛）；
  搬运方案 0.344 < 当前 0.424（不可用）；v613 把 `direct_output` 门放宽到 M≤K 反而 −0.217。

**算术**：21327 + 数十点 ≈ 21350 级别，**远低于 22000**。

## 4. 测量基础设施的硬限制（这也是结论的一部分）

要找 Q/K 机制，本地库必须同时满足两条判据：**T 分布真实** + **Q/K 占多数**。实测：

| 库 | T 真实？ | Q/K 占多数？ | 可用？ |
|---|---|---|---|
| mini_sample / v419_mini_sample | ✓（128/1024） | ✓（87%） | **✓ 但只有 1 组 / 5 例** |
| v1 | 部分（19/45） | ✓（91%） | 10 例，且 player 本身为负（病态） |
| public_quantizer | ✓（512/1024） | ✗（V 78%） | 角色结构反了 |
| structural-v3 镜像 | ✓（到 2048） | ✗（V 79%，且注意力近似均匀） | 角色结构反了 |
| qwen2_5_14b_online_v1 / online_profiled_v2 | ✗（**T≡4**） | ✗ | 名字有误导性 |
| attention_history_fit_v1 / qwen3_8b_profiled_v1 | ✗ | ✗ | 不可用 |

⇒ **我们手上唯一同时匹配判题器的库就是那份官方样例，而它只有 1 组。**
所以 Q/K 机制**无法**在本地可靠排序——这与目标裁决 (3)「线上回执为唯一梯度」完全一致：
本地只能做格式、计时与机制自检。

## 5. 重新开启的条件（具体、可检验）

1. **接口允许实例级对端**（例如同一角色的编码可读取对端已量化的码字、或允许跨角色的一次性缓存）：
   则第 2 节那 90–97% 的 logits 余量变成可达，这是唯一有量级的方向。
2. **判题器形态信息**：attention 的 T 分布与角色占比若与官方样例不同（例如大量短序列），
   则 V 侧权重上升，需重新评估；若大量长序列，则 Q/K 更主导。
3. **新的数学构造**：一类**不需要实例级对端**、又能在保 logits 前提下改善 Q/K 量化几何的机制。
   已排除：正交族（穷尽）、对角族（饱和）、一般 GL(d)（wash）、静态 Gram/GPTQ（饱和）。
4. **判题器评测口径变化**（题量、数据集、时限）——例如 Attention 题量或 T 分布改变。

## 6. 交付现状

- **最佳线上：v636 = 21327 / 260 秒**（Linear：变换块 64→4 + ridge 1e-3→1e-2）。
- v637（+平衡指数 0.30）本地略优、线上约 −2；v642/v651（V 恒等）**已撤回**（T≤4 假象）；
  v643 **非法**（非法尺度乘子，self_check 17/22）。
- 本轮之后，**没有可提交的候选**。

## 7. 方法层面的教训（供后续复核）

本场共 **4 次自我否证**，全部靠"换口径重测"抓出，而非新证据：
1. 「保 logits 只有正交变换」→ 漏掉对角族；
2. 「假对端封死 Q/K 拟合」→ 协议模拟 + 线上分数否证；
3. 「尖峰 ⇒ 恒等方向为正」→ T≡4 混淆否证；
4. 「判题器 V 主导」→ 同样是 T≡4 库喂出的误判（本轮更正）。

**结论：任何本地机制排序必须先过「代表性检查」——T 分布、角色占比、以及度量假设是否与判题器同口径。**

## 8. round 34：用户答复后的重新量化（**并更正一个我引用了多轮的数字**）

用户答复：①（我理解的）允许读取对端实例级码字；②不要参考官方样例；④Linear 上限只有 +550。

### 8.1 「logits oracle 余量 90–97%」这个数字被高估了——它是**小 T 过参数化**的产物

把 oracle 的码字**代回注意力**、按 250 题口径算**被打分的输出分**（`tools/probe_oracle_prize.py`）：

| 库 | T min/med/max | 部署 | oracle Q | oracle Q+K | **Δ(Q+K)** |
|---|---|---|---|---|---|
| `v1`（Q/K 91%） | 4 / 19 / 45 | +0.093858（2347） | +0.701135 | +0.722477 | **+15716** |
| 结构镜像（V 79%） | **64 / 256 / 2048** | +0.681743（17044） | +0.673284 | +0.693031 | **+282** |

- `v1` 上 logits MSE 被压到 **−100%（精确匹配）** ⇒ 输出 +15716。原因是**过参数化**：
  T≤45、dim=256 时码字数远超 logits 条目数，可以精确拟和。
- **真实 T 的镜像上，logits 目标只值 +282**（Q 单独甚至 **−211**，即按 logits 目标重搜 Q 会让**输出变差**）。

**⇒ 我在 round 7 起一直引用的「logits 目标有 90–97% 可达余量」是错的（高估）**：
①小 T 下过参数化；②**logits MSE 与被打分的输出并不同向**——输出经 softmax（饱和）+ V（加权），
所以 logits 误差降 90% 并不等于输出误差降 90%。在真实 T 上，oracle 只能拿回 Q/K 池子的约 6%。

### 8.2 即便"实例级对端"获准，量级也不够

- 真实 T 库上的 oracle 总额 = **+282**；Linear 上限 = **+550**（用户确认）。
- 21327 + 550 + 282 = **22159 < 23000**。
- 若判题器确为 Q/K 主导（86%，但我被要求不据官方样例推断），按角色占比把 +282 放大到 ~+1150，
  则 21327 + 550 + 1150 = 23027 ⇒ **勉强够 23000，但前提是"每一条都打满且假设成立"**；
  按实测杠杆（Linear +23）则只有 ~21400。

### 8.3 但这条路需要**违反三条已记录的禁令**，我不在此口头授权下实现

要拿到实例级 K，Q 的动态调用只能从共享对象里读 K 的码字，这同时依赖：
**跨角色共享缓存** + **调用顺序** + **可变全局状态**——而 AGENTS.md 记录的契约明确禁止这三者
（"动态接口只依赖当前自身输入与对应 state，不依赖跨角色共享缓存、调用顺序或可变全局状态"），
第三方提交要求清单里也写着 "no global mutable cache needed for correctness"。
**这三条与用户本轮的口头"允许"直接冲突。** 我需要在**权威规则文本**（任务书/主办方澄清）里
看到该接口允许跨角色共享，才会实现；否则一旦规则照旧，被取消资格的是用户，而造出那个版本的是我。

### 8.4 无对端、不碰接口的替代：没有量级

校准期使用真实对端**是合法的**（`hif4_calibration_attention` 本来就收到完整的 calib），
但动态期仍只能看到 `q + 自己的 state`，所以只能拟合**静态规则**——而静态族
（正交/对角/GL(d)/GPTQ/逐头精化/网格）已在正确库上逐条验证饱和（见第 2–3 节）。
