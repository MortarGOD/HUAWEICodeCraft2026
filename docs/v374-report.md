# v374：按当前Query方向选择输出误差度量

父版v324，Linear/K/V动态实现保持。不是v365叠加，原父AST完整前缀相同，默认solution.py不覆盖。

## 算法与来源边界

延续APTQ整块重建/一阶Jacobian外积思想，但独立推导本题激活域公式，不是复刻论文权重算法。对校准Query，J=K.T diag(p)(V-pV)/sqrt(d)，H=JJ.T。v365将H平均成每KV头一份，v374按变换后的Query单位方向确定两类，各自平均H，并与父Logit Gram固定50%收缩。

校准使用末份之前的两序列、各至多16个Query和完整K/V，按KV头聚合GQA。两类球面聚类采用确定性远点初始化、四次更新。动态仅用当前Q选择所属类；从父版已量化码字出发，对两个度量各执行4轮修正，再按所属度量实际下降选择整头行结果。所有层级尺度保持，未启用头逐值不变。

不是当前真实K/V条件化H：测试K/V未在Q接口提供，模型只近似校准统计的方向差异。没有跨接口共享测试数据、文件I/O或测试输出缓存。也不是逐Query稠密矩阵分解；状态只保存每头两个中心和两个D×D矩阵。

## 成本/限制

每个启用Q调用新增两个4轮修正；虽然仅选择其中一类，目前仍对全部行计算两份候选，这是明确可进一步优化的冗余，不保证在线300秒。动态仅4≤T≤4096启用。校准Jacobian有完整K维成本，尚未验证线上所有长度和96核性能。

代理数据为缩小checkpoint权重配建模激活，不是线上数据。两类相对单类是否真正贡献收益还缺同预算消融；不能将“多做修正”的收益全部归给条件化。下一步应先做合并度量同轮数对照，再决定增加类别或优化分组计算。
