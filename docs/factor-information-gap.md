# v350拒绝组的信息缺口诊断

本轮仅增加离线诊断，不改solution、Linear、默认入口。6组，每组最后一份校准与最后一份测试，T2048，256个真实query；不是全量收益验证。数据仍是建模激活。

## 对照设计

相同父版V、固定尺度、8轮、I/T²正则，比较：

1. student：v350可部署的V预测概率因子。
2. prototype_exact：相同冻结校准query原型，换成当前真实量化K计算概率；**仅离线oracle**。
3. actual_queries：当前真实量化Q/K构造曲率，交替query拟合/留出；**仅离线oracle**。

每个模式都检查代理目标单调下降。最终输出误差使用原始Q/K/V目标。搜索最小化的仍是V曲率项，不含Q/K误差交叉项，因此代理下降不能保证最终PV下降。

## 结论与下一行动

- **组14/19首先是预测信息缺失**：真实K替换后相同原型已能改善，实际query只是进一步小幅改善。预测概率的归一化集中度约1.8/2.1，而真实K原型约737/1014；模型把高度集中的概率抹平。不能直接归咎于原型数少或8轮不够。
- 聚焦检查发现，每条序列约56%的平均概率集中到一个token，但其位置在校准/测试间变化：组14为70→38，组19为149→558。首8/末8位置并不承载该质量。故**固定首token/首4位置模型不能覆盖这些代理样本的集中结构**。
- 最大V范数也不能直接定位：组14集中token在V范数前8中但非第一；组19校准集中token不在前8，测试在前8但非第一。不能从少数案例硬编码范数最大token或固定索引。
- **组49首先是原型代表性/目标偏差**：替换真实K仍严重失败；换当前query才接近基线。扩大V回归器不能解决整个问题，应研究校准query覆盖或稳健风险，而非共享测试Q/K。
- 组5连实际query曲率也可能损害最终输出，继续保留跨query、跨序列守门，不用训练目标选版本。
- 本次真实原型logits的[-40,40]截断与不截断结果相同，未支持把失败归因于这一步。不能由此断言所有输入截断无影响。

下一可部署试验：先比较对罕见高概率token加权的logit/概率拟合与普通均方拟合，保留序列留出和强正则；确认能识别移动集中位置后再扩大搜索。需要同时报告普通组、集中组和失败组，不按本地group或token索引写分支。尚未实现，无线上收益结论。
