# 统一基线选择扩测及数值可靠性发现

2026-09-05。完整feedback50组250例，原始分数和增量+0.013752651，18升7降225平。变化组0/6/16/20/21，原六组之外220例增量+0.004244072。另一个covariance bank六组30例全部同分。完整结果见 joint-frontier-full.json 和 joint-frontier-screen-covariance.json。两次运行所有JOINT_DEBUG未报告异常，校准状态格式通过。

这些微小差异不能全部归因于选择规则：扩测组6的共同变换候选存在生成成功/失败变化。单独捕获一份父状态，连续6次调用原 `_joint_balanced_states`，输入未变，但2次失败、4次成功。失败发生在第二次 `_upper_cholesky_inv`，该函数捕获异常后返回None，上层仅跳过候选，JOINT_DEBUG.error仍为false。因此“守门无异常”不等于候选生成无数值失败，也不能从通过格式检查推断计算稳定。

## 双精度中间构造原型

新增 stable_joint_source.py：只在共同变换的矩阵幂、求逆、Gram变换、Cholesky等中间计算使用float64；输出joint_transform/u转回float32，H仍BF16，测试量化路径与Linear不改。未调整damping、阈值或候选数。

双精度版本单独捕获父状态后重复6次，全部成功且最终状态逐值相同。原始与双精度实验分别捕获状态，尚未完成同一父状态的跨版本配对对照或广泛泛化验证；不能据此声称所有数值问题已消除。报告为 joint-candidate-repeat.json / joint-candidate-repeat-double.json。

## 决策

暂不封装统一基线规则为正式版本。先验证共同变换构造的数值稳定性、最终输出精度和校准开销；若成立，再在稳定候选上比较选择规则。双精度仅校准中间计算，仍必须通过状态类型、独立接口及300秒预算验证，不能将六次重复稳定直接当成线上收益证据。默认入口与正式版本未改，22000目标未达。
