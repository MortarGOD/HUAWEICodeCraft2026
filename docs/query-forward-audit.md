# Q 搜索前向一致性检查（2026-09-08）

线上最佳仍为 v435=21304/264秒；本检查不生成新候选。

问题：v437 后置共同旋转保留旧 gq/rf 开关，考虑重新选择量化分支之前，必须核实搜索前向是否忠实于动态路径。源码 `_joint_quant_queries` 无条件执行 GPTQ；公共 Q 接口则读取 gq。不能直接把前者用于 RTN 候选。

实验：`tools/audit_query_forward.py` 固定随机种子，序列长度64/256/1152、GQA 2:1、维度64，分别覆盖 GPTQ/RTN 与精修开关的12种组合。在完整序列执行公共接口后抽取相同16行，与模拟函数比较，而不是缩短动态序列改变精修预算。另捕获 attention_feedback_v2 第0/24组配对校准的模拟调用。

结果：gq=1的6组逐值完全一致，包括有/无精修，最大误差0。gq=0的6组各有131–232个元素不同，证明该助手不能模拟RTN。两组真实本地校准共33次调用全部gq=1/rf=1；合成校准没有调用该助手。证据范围有限，不能宣称所有历史/线上调用均覆盖。

短序列32轮、中序列默认轮数、长序列4轮的预算保持一致，未发现此前怀疑的预算错配。实际本地HiF4公共解码结果为FP32，和助手相同；NVFP4输入的BF16舍入要求不代表HiF4输出应额外转BF16。后续不能凭这个误解增添一次舍入。

处置：不发布无证据的“校准修复版”，不修改现有算法。下一步若做新坐标下的分支重选，须实现按候选gq/rf忠实执行、保留原始序列预算的前向；共同Q/K变换保持一致。该排查没有产生线上收益，也不能解释1296分差距。
