# 退化场景与可部署过滤规则

原则：本地退化可用于提出条件，不能直接把组号、模型名称或事后测试分数写进线上if/else。候选必须只依赖当前接口输入/校准state；在未参与设计的组验证，并统计同时挡掉的收益。v381本地负向而线上+65、v379本地负向而线上+4，是不能盲目过滤的直接反例。

| 场景/证据 | 可观测条件与处理 | 当前实施程度 |
|---|---|---|
| v382移走早期温度，组48/49在末端温度之前已大幅损失 | 若早期temperature_gain任一头不为1，保留完整v381，不撤销其依赖；全部单位才试末端温度 | v383已实现；是保守依赖保护，不是完美退化分类器 |
| Linear v372/v373训练改善，跨校准部署退化 | 用未参与拟合的校准序列验证实际Q(A)与Q(W)组合，失败则保留父版 | 历史版本已有守门；不新增I/O比率或尺寸阈值硬禁用 |
| v379/v380训练误差大降而校准折分歧/测试退化 | 保留分折输出守门及训练早停；不能仅靠训练下降启用 | 已有；v379仍线上微正，不能统一禁用所有矩阵训练形状 |
| Q/K混合度量v367线上不如Q单侧 | 以已验证Q单侧为父，K分支仍应独立最终输出验证 | 当前主线不合入v367；没有证据支持按某个head_dim永久禁K |
| 极集中概率的代理组QK误差很小、V主导 | T=1可精确跳过无意义QK优化；T>1的校准集中度只作诊断 | T=1已有；不把“校准近one-hot”当测试必one-hot |
| v369双候选尺度搜索超时 | 停止整套双候选动态路径；运行成本限制优先于继续加候选 | 主线未合入；没有96核逐形状测量，不伪造可靠秒数阈值 |

## v382的具体特征

三个负组4/48/49均有早期温度修改（4/2/6个Q头）；但正组0/14/47也有修改，所以规则会同时挡掉一些收益。head_dim也不能精确区分：512维既有正组14/19也有负组48/49；256维同样有正有负。详细原始特征见temperature-risk-profile.json，组号仅用于离线定位，未写入提交文件。

v383不在两套完整组合间反复竞争：先运行v381，如果存在早期温度修改则直接返回同一state；否则保留整个v381状态，仅尝试一次末端温度，并沿用原始实际输出两折守门。被保护的输入不增加候选计算，不改变Q/K/V返回路径；未保护输入仍可能在测试上退化，不能承诺全数据不退化。

## 使用限制

本轮只落地具备清晰依赖解释的温度保护规则，其他条目区分已有保护和待研究假设，没有将所有经验硬编码成新路由。后续新规则必须同样有当前接口可见特征、机制解释、独立组反例与成本记录。
