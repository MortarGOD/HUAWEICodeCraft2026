## 定位剩余误差

在固定真实checkpoint投影bank前10组50题上，用不可部署的分项oracle做诊断：

| 条件 | 原始代理分 |
|---|---:|
| v309实际算法 | 17.238678 |
| Q/K完全无误差，V保持量化 | 19.859307 |
| V完全无误差，Q/K保持量化 | 47.430373 |

这不是线上上限证明，也不是候选得分；但明确说明**当前代理上的主要剩余误差在V**。因此不再盲目增加Q/K轮数。已尝试的单坐标直接跳档、块Newton重选尺度、NumPy活动集、扩大尺度搜索均留存结果：小幅增益不足以抵消运行成本，没有融合。

一个需要纠正的理解：V输出通道之间没有额外投影，并不意味着V只需逐元素MSE。`PV`仍在token维度混合，V误差的真实二次度量包含`PᵀP`，而不是token维度的单位阵。此前针对V的单位通道Hessian refinement确实无效，但这不能排除跨token优化。本版用秩一均值项加对角项近似这部分耦合。

## 算法与论文思想的关系

沿用docs/Attention_opt.md中“优化最终PV输出而非仅V逐元素MSE”的任务目标，以及GPTQ/BOA二次误差建模思路。本版不是原样复现某篇论文，而是针对固定HiF4表示与独立V接口推导的可部署近似。

令误差`e_t=V_t−Q(V)_t`。若Attention权重在token间可交换，且忽略它与量化误差的依赖，输出误差的期望包含：

`J = mean(e)^2 + λ · mean(e^2)`。

更具体地，记权重平方和的期望为S，归一化后的`λ=(T·S−1)/(T·(1−S))`。当Attention较分散时，λ约为常数/T。本版固定取`λ=1/T`，不是在线测得S。若Attention近乎one-hot或强依赖V误差，该代理会失配，必须由线上验证。

实现：

1. 保留v309为V选择的HiF4 scale_factor/lv2/lv3；不改变格式和尺度结构。
2. 按通道计算当前输入V与量化V的均值误差。
3. 8次迭代：给原V加一个通道偏移，在原尺度上舍入到合法signed code -7..7；用`mean-error² + MSE/T`验收每个通道的整列候选，偏移按当前均值误差以0.75步长更新。
4. 始终保留初始候选，所用代理目标逐通道不增；不声称真实Attention输出误差必然不增。
5. T=1时V不变。根据self_check第553行的Q/K/V长度相同约束，T=1时softmax恒为1，因此Q/K只做普通合法量化，跳过不影响输出的GPTQ/refinement。

只使用当前V及其量化结果；不读取当前Q/K、不传递额外state、不做文件IO或跨接口缓存。Linear、非T1 Q/K和校准逻辑冻结。

这里的均值误差指**当前序列**的误差均值；即使量化器在总体上无偏，有限样本仍可能存在这一误差分量，不能由本地收益推断总体量化误差一定有偏。
