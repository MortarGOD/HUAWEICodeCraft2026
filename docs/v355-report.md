# v355：概率行为覆盖Query原型探针

v355以v353为父，不叠加v354。V条件概率因子仍为16个、风险搜索8轮、正则1.0、独立末份校准PV守门不变；差异是从两份训练校准的量化Query中，以128个固定采样Key上的softmax概率向量作为行为特征，采用均值附近起点和最远点覆盖选16个真实Query，并按最近代表簇频率形成非负归一化权重。动态风险因子乘以权重平方根，使二阶项对应加权概率风险。

新增state仅为每KV头16个有限float32 `query_weights`；不增加动态因子数、搜索轮数或测试阶段矩阵规模。Linear、v353三角Gram恢复和校准缓存不变。

## 发现并修复的生成器问题

首次生成器重新输出风险核心时，把正式v353的 `_AF_SEARCH_RIDGE=1.0` 静默恢复为研究默认0.1。该错误配置完成了60例，合计−0.273474；结果保存在 `v355-ridge01-invalid-regression.json`，不得作为正式v355结论。生成器已显式断言原默认仅出现一次并替换为1.0，实际v355两处常量均为1.0，随后重新执行全部验证。

此前 `query-coverage-report.md` 声称覆盖配置“正则仍1”不准确：当时的coverage_source同样重新定义为0.1。旧数值保留为历史错误配置证据，不再用于比较正式v350。该偏差也解释了为何本轮必须以实际最终文件验证，而不能只依赖研究命名。

## 修正版验证

- 覆盖选择、权重和显式二阶风险42项检查；实际回归中的权重有限、非负、逐头和为1。
- 实际生成源码AST与v353+修正后的覆盖源码逐项一致；禁止模块和动态I/O/执行调用扫描通过。
- 官方self_check接口6/6、输出格式22/22通过。
- 实际v353/v355两bank各6组共60例：feedback合计+0.010526603，covariance合计−0.143200822，总计−0.132674220。变化39例；结果方向冲突，不具备稳健本地优势。
- 单轮12组校准合计v353/v355为26.57/22.00秒，v353首组包含明显冷启动，并非完整端到端计时，不宣称加速；动态预算相同。

## 决策与预估

本地结构bank明显退化，因此v355不替代v353。按照用户要求，本地不能100%证明线上劣化的独立方向仍保留并推送，可作为低优先级线上探针；线上若更接近feedback分布可能小幅变化，但没有依据预测+50，更不能预测22000。300秒仍需线上验证。默认入口和Linear不覆盖，首选仍是v353。
