# Mrxxx7/test 全分支分析与迁移建议

日期：2026-09-07。源仓库：<https://gitcode.com/Mrxxx7/test.git>。研究对象为本次抓取的全部 24 个远端分支，以及与其算法和成绩有关的历史版本；对照本项目 `solution/solution_v419.py`。本轮完成拉取、源码导出、版本与回执追溯、算法比较，未运行参考算法或评测，未改本项目算法入口。

## 结论

**有值得利用的实现和研究点，但没有证据支持把某个分支整体替换 v419。** 本次比只看 `base_1.7` 多获得三类认识：

1. Linear 的补偿范数限制、八通道候选去重、批量坐标验收和状态数值范围处理，有具体工程借鉴价值；完整输出拟合、GPTQ、平滑和旋转本身已经在本项目存在。
2. K quotient 目标把量化误差、梯度、曲率及接受式一起投影，去除 softmax 不敏感的 token 常量方向，是值得优先分离验证的新候选。历史高分版本中的短序列 V 完整 token 二阶目标、双点更新和微指数子树修正，也值得单独研究。
3. 版本身份、校准协议和评测分布是判断结果的前提。名称中的 `safe`、`inputisolated`、`36k` 均不足以证明适用；某些源码与同目录 ZIP 有实质差异，同一源码也出现过不同历史分数。

建议先延续上一轮的 **Linear prepared 复用**；精度方向先分离验证 K quotient 的简化目标。随后比较有界坐标搜索的批量组织，并将补偿范数限制作为附加中心候选。V 先验证二阶模型在三次角色校准下是否有效，再决定是否移植求解器。

## 3. Linear 最值得借鉴的部分

### 3.1 给连续补偿增加基于校准的幅度限制，但保留父结果

runtime170 在变换坐标中，先从固定 W 与部署权重 B 求连续补偿 δ，再统计每个校准行的相对补偿量：

```text
r = ||δ|| / max(||a||, ε)
ρ = max(1.5 × quantile(r, 0.95), 1e−4)
δ_guarded = δ × min(1, ρ ||a|| / max(||δ||, ε))
```

它限制补偿向量，不裁掉原激活。v419 的连续投影有 ridge，但未见这种按校准分位数限定动态补偿范数的机制；最终 MSE cap 与这个候选中心限制也不是同一件事。

**迁移方式：** 先只把受限中心作为附加候选，保留未限制的原中心和完整父结果，按本项目实际完整目标验收。若直接替换父中心，会缩小搜索范围，可能丢掉原有收益。校准与动态应使用相同坐标和实际冻结精度。

证据仍有限：参考发布数据上 guard 没有触发；构造放大方向证明它能限制补偿，但没有证明会改善真实分数，也没有证明修复了历史 WA。因此最小实验应先记录自然触发、实际改码、拒绝原因和额外开销，不能仅测合成例子就合入。

源码定位与旧报告反例见 [unrestricted 审阅：补偿范数限制](test分支审计-20260907/unrestricted-methods.md)。

### 3.2 候选去重、排序前缀和批量残差验收

runtime170 的有效搜索并不等于目录名描述：64 通道阶段实际 top-k=0；八通道阶段选择 top96 并一次处理，标量阶段先 top512 再补最多512，以 batch28 处理。

八通道的两个 quartet 有八种 lv2/lv3 编码，但只产生七种不同的有效倍率对。参考删除重复倍率候选，再用当前输出残差检查合并更新，避免把多个独立有益坐标简单相加后遗漏交叉项。缺点是整批拒绝可能丢掉有益子集。

与上一轮 `base_1.7` 的 top-k 前缀搜索结合，可形成一个具体对照：

- 在固定父结果后，只增加少量坐标/微组提案；复用现有 Gram、梯度及元数据。
- 先廉价排名，再对排序前缀或小批组合计算完整交叉项，接收最佳下降候选。
- 把候选数量、批量大小、重复候选、整批拒绝率及时间分别计数；同精度提速与改变搜索预算的精度变化分别验证。

本项目已有 64 块 Newton、micro 更新、完整 Gram 和输出目标验收。可利用的是计算组织，不能把“考虑输出误差”当新增。参考 runtime 的 B/E/补偿矩阵采用 FP16，其严格下降也只针对该冻结 state 定义的目标；迁入时应以本项目原始教师与实际部署目标验收。

### 3.3 状态压缩有维度条件，不能套用百分比

一个 runtime160 变体不保存 O×I 的补偿矩阵，而保存 O×O 的逆矩阵，并用 FP32 行尺度与 FP16 归一化值避免直接 FP16 inverse 溢出。动态再乘 B 恢复作用。

其“节省约87.4%”只针对 O=256、I=2048 时的一块补偿状态，不是全部 state。O>I 时这可能更大；v419 的 O<I 已走直接输出编码，O>I 则已有输入侧 I×I 投影，机械照搬没有尺寸依据。只有实际 profile 显示 state 复制/还原是瓶颈，才值得比较因式存储。

### 3.4 学习变换必须对齐最终部署量化器

历史 SmoothRot、RRS、InfoQuant、Spin-LWC 等方案提供了缩放、有限个 Householder、Cayley/STE 和低成本反射实例。不同分支中常见“拟合用一个量化器、最终用另一个候选半径”“计算了补偿但未进入 state”“最后代码覆盖前面实现”的情况。

值得吸取的原则是：**校准选择必须用最终实际部署的 Q(W)、state 精度和动态量化路径重新评分**。连续补偿输出的误差更低，不等于重新量化后的误差更低。某些历史实现只在末端 offset 选择对齐最终权重，不能把这种局部刷新描述成整条训练链完全一致。

例如 24628 对应版本在校准数量为 2 或 3 时会形成空验证集，并在返回 state 时除零；历史 All passed 不证明它覆盖任意合法校准数量。其投影补偿虽被计算，却没有进入最终动态 state，不能当作这份高分的实际机制。

便宜的平衡/FWHT/少量反射仍可作为替代全宽 polar 的候选；这是精度/成本交换，要保持后续搜索预算相同再比较。本项目已有相关变换和部署一致性研究，不按论文名称重复开发。

## 4. Attention 可以学习什么，哪里不能直接搬

### 4.1 历史 25062 方案：短 T 完整 token 二阶结构

该候选在校准阶段估计 V 的 `E[PᵀP]`，收缩后保留 token 之间的非对角耦合；动态只看当前 V 与冻结 state，以单坐标、双 token、lv3 子树候选及后续修正优化合法量化值。比只优化逐张量 MSE，它更接近固定 P 下的最终输出风险。

“短 T”是本报告建议的实验边界，原实现没有明确的短 T 上限；它要求各校准 T 相同，动态 H 形状必须正好匹配当前 `[kv_heads,T,T]`，否则回退基础量化。完整 H state 随 `kv_heads×T²` 增长，不适合未计预算就推广到长序列。

可研究的是这套**短 T 完整二阶结构 + 收缩 + 双点/子树更新**的具体组合。本项目已经有均值风险、静态位置二阶模型、位置谱、自适应概率因子、双点搜索等：

- [v348/v349](v348-v349-report.md) 已研究显式位置与背景的联合矩；
- [v356](v356-report.md) 的静态谱单独迁移负向，小权重补充略正；
- [v412](v412-report.md) 的线上闭合对照支持最终保留 VK、剥离 VR/VM。

所以不能称“首次发现 V 的 token 耦合”，也不能仅凭旧高分重新叠加所有分支。应先用短 T 的完整矩阵对照现有因子模型，再单独加入双点或子树候选，分清风险模型改善与搜索改善。

**必要条件：** 冻结的 token Hessian 需要跨校准/测试序列具有可迁移性。动态独立不代表校准配对真实；在当前 V 校准只保留真 V、Q/K 为假对端的条件下，所得 P 的含义必须重新验证。长度、位置变化以及统计收缩均不能跳过。

### 4.2 Quotient/Givens：利用 softmax 的无效方向，但共同变换要匹配

softmax 对每个 query 的 logits 加同一个常数不变，所以 K 的共同 token 平移不改变精确概率。quotient 方案把这个无效方向从误差目标中排除，并在 token 之间耦合验收；另用有限的 Givens 旋转重新分配量化误差。

这两点必须分开：去除 softmax 无效误差是数学结构，Givens 的收益则取决于实际双方变换与量化。Q/K 由同一次配对校准选择同一个变换时成立的关系，在三次独立角色校准下未必成立。参考 isolation 测试只用一次配对校准，再验证新模块、调用顺序和插入样本；它没有覆盖我们已知的校准条件。

本项目已有 K 平移/Lloyd、输出 Jacobian 度量和共同变换研究。可提取 quotient 目标或小型旋转的候选形式，但必须保留跨 token 交叉项和双方一致性检查；不能把名为 `inputisolated` 当作免验证证明。详细实现、ZIP 差异和角度拟合留出边界见 [独立接口方案审阅](test分支审计-20260907/isolated-methods.md)。

**更有价值的最小版本不需要一起迁移 Givens。** 在本项目已有的冻结共享 H 下，令 E 为 K 量化误差，优化 `L=Σ_t (E_t−mean(E))ᵀ H (E_t−mean(E))`。单 token 更新 δ 的精确增量是：

```text
ΔL = 2 δᵀ H (E_t−mean(E)) + (1−1/T) δᵀHδ
```

多个 token 同时更新时，完整增量为 `2Σ_t δ_tᵀH(E_t−mean(E)) + Σ_t δ_tᵀHδ_t − (Σ_t δ_t)ᵀH(Σ_t δ_t)/T`，不能把单点收益直接相加。这里投影的是**量化误差及其搜索目标**，与只在量化前把 K 减均值不同。当前 K 与冻结 H 足以计算，先保持父变换、编码格点和搜索预算不变即可研究；不需要当前真实 Q，也不需要复制参考的逐 token 大状态 `H_t/F_t`。T=1 时该目标为零，必须稳定回退。上述公式是数学推导，尚未实测，代理下降仍不保证真实输出改善。

### 4.3 当前 QK 缓存路径不具备迁移的信息条件

runtime/headadaptive/PSOT/Compensated V2 的强联合路径缓存当前真实 Q，然后 K 使用它修正真实 logits 或概率，V 再拟合当前真实 `PV`。logit-basis 还会把 Q 重编码成确定基底，由 K 借助缓存的真实 Q 重建目标 logits。

其中若干方案保持了返回逻辑宽度，不能笼统归因为“扩展维度”；它们的直接障碍是**当前真实对端不可见**。清理旧 cache、校验 shape、绑定 Q→K→V 顺序，只能减少错误配对，不能解决独立接口的信息缺失。

可以学习有限步最小二乘、增量残差、短序列组合搜索、保留当前候选和压缩误差界，但必须另建合法目标。预测 P 与真实 P 的模型误差，不能由 P 的压缩误差界代替。参考先形成完整 QKᵀ 再采样/压缩，也不等于端到端消除了 T² 内存。
