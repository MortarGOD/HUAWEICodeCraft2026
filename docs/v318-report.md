# v318：保留已验证算法，优化执行与长校准覆盖

> 线上已确认 **20208分/249秒**，与v317同分、快11秒（4.23%）；以下发布前估计保留追溯，当前父版更新为v318。

## 结论和版本边界

父版v317线上20208分/260秒。v318不是声称可以再涨200分的精度版本：本轮新增精度候选没有达到足够的收益证据，因此没有合入。应将本版视为**性能、峰值工作内存和校准覆盖修复候选**，保留v317回退。

当前入口solution.py与独立solution_v318.py相同。Linear所有函数及参数冻结v317。Attention保留原GPTQ、refinement、旋转/平滑、矩阵配平、V均值反馈/条件kernel、Q增益；不加入v316线上零收益的framebank，不改动态轮数，不增加测试搜索。

26个仓库的逐入口梳理、与当前实现的对应关系、未用算法和接口限制，见 [参考审计](v318-reference-audit.md)。下载不等于完整逐行审计，更不等于全部算法已落地。

## 正式合入三项

1. **GPTQ signed-code scratch**：保留32列分块、原浮点运算次序和误差传播，直接在输出缓冲做除法/舍入/有符号码裁剪；删除abs/sign/where等中间数组、复用误差缓冲，去掉已处理列无人读取的回写。参考QuIP#和GPTQModel的连续布局/工作区原则，独立实现，不拷贝第三方运行框架。
2. **校准Attention按query分块**：对T>512的`_attention_out`，每次最多256个query，并按qh×T调整到约400万个score元素。仍计算调用输入的每一个query和完整key，softmax分母不截断；避免一次性T×T score/prob分配。数学目标不变，浮点累加存在微差；513行单测最大绝对差1.64e−7。**原早期rotation/refinement调用本身的key抽样策略仍保留**，不能宣传为已修复所有部署守门偏差。
3. **长校准Gram覆盖**：旧版直接丢弃T>1024的拟合样本；现在均匀选1024行，以T/1024乘回统计贡献。末份校准仍排除。内存/矩阵乘法有界，不等于对任意序列的全行精确Gram，也不是无偏随机估计。只在长拟合样本存在时改变这一部分；当前feedback_v2的拟合长度不覆盖此收益。

第二项参考低精度Attention工程的分块/峰值内存管理，但不是移植SageAttention CUDA内核或FlashAttention完整算法。没有新增导入、文件读写、编译或跨接口共享缓存。

## 性能与线上预估边界

串行正反顺序、纯接口、三组固定输入：父版两次7.78/15.92秒，新版8.85/14.05秒；合计比值约0.966。波动明显，不能据此断言线上精确快3.4%，更不能拿单个GPTQ内核的20%代替整场20%。原始记录为v318-release-interface-timing.json；v318-interface-timing.json属于被否决的抽query实验，不能混用。

工作参考：**分数接近20208，耗时约240–280秒，均低置信度**。这不是达到+50精度门槛的保证；若线上存在旧版完全跳过的长校准组，精度和动态开销都可能变化，现有bank无法量化。300秒仍是硬限制，280只是内部目标而非保证。
