## 结论

**有可借鉴点，优先考虑 Linear 的计算复用与有界坐标搜索；Attention 的核心联合优化不能直接搬入现有独立角色接口。** 参考方案的大部分基础手段在本项目已存在，真正需要提取的是不同的候选生成、计算组织和验收方法，而不是再堆一套 GPTQ/平滑/输出拟合。

| 优先级 | 借鉴点 | 对本项目的具体意义 | 首要验收 |
|---|---|---|---|
| 1 | 同一输入的多尺度候选共用预处理 | v419 的 Linear 初始候选可以复用已有 `prepared` 接口，消除重复峰值/编码计算 | 全部参数逐项完全相同，再测耗时 |
| 2 | 固定网格的 top-k 坐标前缀搜索 | 在现有结果后试少量跨 64 块更新；已有完整 Gram 时避免输出空间大临时张量 | 真正输出目标不增、实际改码和有限开销 |
| 3 | 每 64 通道最多两个 Householder 反射 | 作为全宽 polar 的低成本替代候选，研究校准速度与精度取舍 | 配对变换不变性、最终误差、分阶段计时 |
| 条件性 | PCA / int8 输出草图 | 仅作为低成本提案或筛选器，保留本项目完整目标验收 | 草图排序与完整目标一致性、漏选和退化 |
| 条件性 | 避免显式构造正规矩阵的 V 求解、离散候选和压缩误差界 | 方法可改写到当前合法代理 P，但不能使用参考代码的真实 Q/K 缓存 | 代理误差与真实留出误差分别验证 |
| 不直接迁移 | 当前 Q 误差补偿 K、真实 P 下联合 V 重建 | 依赖 Q→K→V 同模块全局缓存 | 当前独立接口不具备这项信息条件 |

## 2. 本地高分与本项目不能直接比较

V2 报告的本地分数为 Linear `248.81740872625605`、Attention `212.98531680811325`、总分 `461.8027255343693`；这是其本地 500 case 的结果，不是本项目平台分数。配置要求每类 50 组、每组 5 份测试，即 250 Linear + 250 Attention；本项目当前是 50 + 250。

该 [compact trace](papers/hif4-public-references/test/doc/Qwen2.5-14B线上比例trace.md) 每份 Linear 激活只有 2 行，权重只保留 32 个输出行；Attention 测试为 4 token。前者恰好触发小样本反射和降维分支，后者没有覆盖 V2 新增长路径。构造长序列测试由公开 trace 行拼接，不能称为原模型连续长上下文；文档也明确禁止把这些本地结果换算线上分数。V1 本地长序列改善却线上同分，说明这种外推不可靠。

该目录的 profiled v2 也不是线上原始数据恢复结果：[数据审计](papers/hif4-public-references/test/online-dataset-profiling/PROFILED_V2_ANALYSIS.md) 明确标记为尚待验证的代理数据。它人为增强 Linear 块内相关性和通道能量差异，并将校准样本向组中心收缩 25%；80% Attention 组将 Q/K 缩放至 0.85，按校准 V 做通道均衡。作者明确不建议用它精细排列 Attention 策略优劣。故这里的高分可能反映对这种构造分布的适配，不能直接推断对本项目数据的泛化。

评分分母也不同：[内部基线说明](papers/hif4-public-references/test/doc/判题器实现约定.md) 明确不宣称是官方实现。其 [hierarchical_v1](papers/hif4-public-references/test/tests/judge_src/fourbit_judge/references/hierarchical_v1.py) 默认搜索三个相邻 E6M2 scale，再按 FP32 重构误差选微指数树；本项目 [hif4_quant.py](../hif4_quant.py) 使用 absmax/7 向上取 E6M2、阈值 4/2 选微指数。参考逐题分数为 `(MSE_base−MSE_test)/max(MSE_base,1e−12)`，双零记 0，不截断负分；该 500 case 配置直接求和，没有乘 100。即使调整用例数与分值尺度，基线差异仍无法消除。

更关键的是执行协议：[本地 evaluator](papers/hif4-public-references/test/tests/judge_src/fourbit_judge/evaluator.py) 每组只做一次配对 Attention calibration，再使用同一组函数按 Q→K→V 调用。[worker](papers/hif4-public-references/test/tests/judge_src/fourbit_judge/submission/worker.py) 在同一次评测请求中导入并复用提交模块；复制 state 并不隔离模块全局变量。它没有实现本项目已确认的三次“真自身 / 假对端”校准及动态角色独立条件。这个私有判题器的 `valid` 只能解释为符合它自己的协议，也不代表每个 case 都有正收益。

此外，[profiled v2 配置](papers/hif4-public-references/test/configs/qwen2_5_14b_online_profiled_v2.toml) 设置 600 秒、16 GiB、4 线程。发布说明没有给出足够信息来锁定每个报告使用的确切命令；不能把该配置下通过或本机耗时当作本项目 300 秒限制的验证。

另外，`doc/违规实现清单.md` 中 08-29 禁止动态利用 W 的判断早于本项目当前规则；不能拿它否定现在允许的 Linear `A@W` 目标拟合。相反，当前 Attention 的真实对端不可见问题仍然存在，不能因 Linear 规则放宽而一并忽略。

## 3. Linear：主路径、增量和限制

下文 N 表示 [参考 solution.py](papers/hif4-public-references/test/solution/solution.py)，R 表示 [本项目 v419](../solution/solution_v419.py)，行号均对应本轮实际文件。

### 实际算法

1. **输入解码与投影。** N:91–94 保留 BF16 解码舍入。当输出维度小于输入且权重少于 8M 元素时，N:1130–1142 使用 FP16 QR 基把激活投影到 W 行空间。精确正交基下不改变 `AWᵀ`，FP16 基只能近似。本项目降维已有直接输出 decoder，不能未经对照把该投影叠到 decoder 前后。
2. **常规校准路径。** 至少两份校准时，直接使用互补平滑与 64 通道 Hadamard。只有每份校准不超过 4 行时才增加最多两个块内 Householder 反射；不是所有输入都有反射，也不是常规路径自动搜索所有变换 family（N:1117–1248）。
3. **权重候选。** 用校准激活构造 64×64 二阶矩，对非对角项按噪声收缩；搜索合法 E6M2 邻域，先以对角重要性选微指数树，再以块二次型比较候选（N:1006–1046、492–652）。后一步不使前一步变成全二次目标下的微指数穷举最优。
4. **激活连续补偿。** 有条件地存储由 W 与部署权重 B 得到的补偿矩阵，再对当前 A 校正。形式为 `A_c = A − A(B−W)ᵀ(BBᵀ+λI)^−1B`。本项目已经有连续投影、真实目标权重与完整输出误差搜索，此原理不是新增（N:930–965、1845–1857；R:1093–1176、2066–2206）。
5. **离散输出搜索。** 初步层级量化与块内码字修正后，N:1711–1811 在固定尺度上按行选择 top-k 通道，并比较排序前缀在完整权重或解包草图所定义目标下的联合误差变化。k 根据形状为 4/8/16，每个方向限于 ±2 码，最终只改 sign/mant。

### 最值得借鉴的坐标前缀搜索

令部署权重为 B，当前误差为 `r = ÂBᵀ − AWᵀ`，`g = rB`，`G = BᵀB`。单坐标改变量 δ 的精确二次增量为：

```text
ΔJ_j = 2 g_j δ_j + G_jj δ_j²
```

参考代码按此量排序，但没有直接同时接受全部 top-k：它累加前缀的输出变化，再计算完整交叉项并选择最优下降前缀。这能避免多个单独有益改动组合后互相干扰，也允许在一次提案中改变不同 64 块的通道。

本项目当前主要按 64 块和块内 micro 更新，因此可以在完成父结果后加 **1–2 轮**有界对照。对已有完整 Gram 的形状，直接用选中通道的小子矩阵计算：

```text
ΔJ = 2 gᵀδ + δᵀGδ
g_new = g + δG
```

这样不必照搬 `rows × k × outputs` 的前缀临时张量或每轮完整输出乘法。符号需与本项目残差定义对齐。

此算法只枚举排序前缀，不是全部组合或全局最优；当单坐标取整方向全为零时也未必能突破离散障碍。验收需记录合法参数、实际改码、完整目标差值、停止原因和时间；不能把“多坐标”本身当作收益证据。

### 更保守的速度机会：复用初始候选预处理

N:492–652 的多半径量化器共用输入幅值、峰值及同尺度误差。R:1219–1227 对同一 center 的多个 `(offset, threshold)` 分别调用 `_quantize_linear_values`，但 R:163–190 已经支持 `prepared=(groups, weights, peak_code)`，此处未使用。

可以先只按 center 复用 groups/peak_code，将这部分从每候选重复计算改成每 center 一次，保留所有候选、舍入阈值、遍历及相等时选择顺序。不同 threshold 的码字误差不能误当相同而共享。该改法有清楚的逐字段完全相等验收，优先于改变数值算法；尚未测量收益，不能承诺节省几秒。

参考 V2 提到的“最后才生成 mant”和“用绝对值计算误差”，本项目 R:2277–2342 已有；R:2346–2428 还做了候选小批量和 scratch 复用。这些不应再包装成新增优化。

### 低成本变换与状态草图

N:221–279 的 `H=I−2uuᵀ` 块反射对 A/W 使用同一正交变换，每 64 通道最多两个方向，可用小矩阵特征分解和 rank-1 更新执行。R:1718–1758 使用全输入宽度 Gram 和特征分解的 polar whitening。前者可能降低校准及动态变换成本，但保留的相关性结构不同，必须作“父 polar / 无 polar / 块反射”三项对照，不能称作保持输出不变的性能重构。

N:839–927 的 `exact_output=True` 容易误读：输出较宽时，每 64 输出保留若干 PCA 方向，默认上限 56，大权重上限 24，再按 14 Mi 元素预算下调；不足 24 时停用。投影权重与投影残差再按 16 通道 int8+FP16 scale 打包。搜索对解包后的投影目标精确，不是对原完整输出精确。它适合作为筛选器或状态/预算受限的备选；本项目已有完整目标和部分形状的完整输入 Gram，应保留最终完整目标验收。

两处不宜照搬的实现细节：

- 常规多校准路径在 N:1248 前已返回；后面的 `_linear_channel_stability` 路径面对少于两份数据又返回 −1。因此不能把后半段 family 稳定性选择当作常规五份校准时有效的保护。
- N:1895–1907 的工作量判断可以把轮数压至 0，但 N:1937–1942 仍执行 16 轮 fallback；该常量不是硬计算上限。借鉴时须核对完整回退成本。

## 4. Attention：联合优化为何不能原样借用

### 真实当前张量的缓存链

N:3720–3791 的 Q 入口把当前 `q_reference/q_value` 写入 `_ATTENTION_SAMPLE_CACHE`；N:3901–3939 的 K 入口没有该缓存时直接走独立量化/块修正回退。正常串行路径会利用 Q 选 K，并在 N:4115–4127 把当前 K 与真实/设计概率继续写入缓存。N:4657–4747 的 V 入口没有 `stage='k'` 的缓存就直接返回自己的基础结果，最后清空缓存。

因此，把文件放进独立 Q/K/V 模块，并不会自动得到它文档中主要的联合 K/V 优化；路径会回退。这是源码控制流上的确定条件，无需根据总分猜测。使用同形状校验也不能替代同样本绑定，不能将该缓存设计引入本项目。

### K 补偿的数学思路

N:3817–3898 先去 K 的共同 token 均值，再解：

```text
K_desiredᵀ = (Q̂ᵀQ̂ + λI)^−1 (Q̂ᵀQ K_centerᵀ + λK_initialᵀ)
```

随后做整 head 的 GPTQ，每 64 通道重新选择 HiF4 层级，并以真实 Q 产生的完整概率误差按 KV head 接受。它把误差补偿放在特征空间小系统中，有算法价值；但 Q 和 Q̂ 都是当前样本真实 Q，独立 K 接口不可得。若改用校准预测，目标、误差与接受证据已经改变，不能沿用原报告收益。

另外，K 接受依据是概率误差，不是最终 Attention 输出误差；即便拥有真实缓存，也不能据该守门证明整条 Q/K/V 链一定改善。

### V 求解、压缩与验收

参考实现按长度划分短序列码字/层级修正、65–256 token 联合重建、长序列采样及压缩算子路径。V2 的压缩路径（N:4131–4248）使用 FP16 dense 或 CSR 保存概率，做 4 轮预条件共轭梯度，生成连续修正，再重新量化完整层级，按 head/64 通道块选择。

其理想修正方向对应：

```text
(P̂ᵀP̂ + λI) Δ = −P̂ᵀ(P̂V̂ − PV)
```

实际以压缩算子替代 P/P̂，只迭代 4 轮，再限幅、重新量化与验收，不是精确求解原方程。矩阵乘采用 `P̂ᵀ(P̂d)` 的形式，不必显式构造 token×token 正规矩阵。不过，N:4013 调用 N:1056–1062 的概率函数时，已经先构造完整 `QKᵀ` 和 softmax；后续采样或压缩没有消除最初 `O(q_heads × T²)` 的概率构造与存储峰值。它仍需要真实参考 P 与设计 P̂；当前 V 接口不具备这些输入。

比较精细的工程点是压缩误差验收：每行保留 `ε_i = Σ_j |P_ij−P̃_ij|`；对输出块，利用 `ε_i × max_j ||V_j,block||₂` 给出输出扰动界。只有候选误差上界低于基线误差下界才接受，计入了省略和 FP16 舍入的概率质量。数学上这是对**已知 P 的表示误差**的保护，不是未知真实 P 与预测 P 的模型误差界。

### 与 v419 的重复及适用边界

本项目已有整 head GPTQ、当前 K 平移、V 均值协调、当前 V→概率代理、残差情景、低维相关求解和离散边界预算。v419 最终状态会剥离 VR/VM，不能因为这些函数仍在源码里就把它们算作最终动态路径。

v419 最终 `_rb_refine` 的相关求解只处理代理 P≤128 行、T≤4096 的形状；在这个处理范围内，每个活跃 KV head 的 P 至多约 2 MiB FP32。但它先构造全部头的 P，再筛 active、检查行数，上游 `_vk_refine` 也没有 128 行门槛；sigma 情景和 GQA 比例可使代理更大，2 MiB 不是全路径峰值上限。参考实现的全真实概率则可能随 T² 增长。对 RB 当前处理的小系统，直接上 CSR、FP16 或四轮 CG 未必更快。尤其分散概率通常难在 `1e-6` 阈值下稀疏，参考 CSR 平均每行超过 64 个非零就放弃；这个稀疏条件不是所有注意力都成立。

可保留的研究方向有两个：

1. 把参考的有界离散 token 更新作为当前合法 `P_proxy` 风险下的候选生成器，保留 v419 的父结果、MSE cap 与接受标准。只比较一个组件，并在角色独立留出测试中记录代理/最终误差是否同向。历史 v392、v399、v413 的求解器改动已经出现本地正向而线上负向，不应直接提高这条路线的预期。
2. 只有将来代理规模真正成为内存/计算瓶颈，才比较压缩或矩阵无显式展开的求解方式。压缩界可保护未压缩的同一代理风险，无法赋予真实 Attention 改善保证。
