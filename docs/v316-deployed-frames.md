# v316：以实际 GPTQ 输出重新选择 Q/K 坐标

## 线上依据与版本边界

v315=20189/259秒，比v314=20071/241秒增加118分、增加18秒，成为新父版。距22000还差1811分。本版Linear、V算法、原有温度拟合与长序列refinement预算均保留；只改Attention校准坐标选择及对应动态分发。父候选保留，v315为回退。

旧Q/K平滑选择发生在RTN阶段；后来开启GPTQ/全矩阵变换，原先选择未必仍最优。本轮不是重新堆refinement轮数，而是让坐标候选直接经过最终HiF4/GPTQ/refinement和实际V的完整输出评价。

## 实现

1. 父版最终Q/K状态作为候选0，包括已经选择的Q头temperature_gain、GPTQ及refinement开关。
2. 候选1删除旧通道平滑与密集配平，使用共同的seed0普通旋转；候选2仅在有旧尺度与密集基底时删除尺度、保留各自密集基底。不重新拟合多档尺度，不增加训练迭代。
3. 从前面的校准样本（原有统计口径T≤1024）重建原始Q/K Gram；用新基底合同变换生成新H/U。K的Gram包含同组每个Q头temperature_gain的平方权重，防止新统计与实际部署不一致。Q头增益保留，但不声称它在新坐标下仍是最优。
4. 最后校准样本最多64个Q行，完整K/V；比较真实softmax(Q̂K̂ᵀ)V̂与原始输出，按共享K组共同选择Q/K。奇偶两折都须至少改善0.5%。父V固定，无测试标签参与选择。
5. 仅把用到的候选和父回退写入state。动态接口独立处理自己的输入，只运行选中的候选；T=1回到父路径。混合GQA组时逐64通道块一起选择全部HiF4元数据，不混用不相容尺度。
6. 同次校准复用温度守门已经计算出的Q/K/V与目标；上下文只在该调用的局部变量中传递，不放进返回state，不用模块全局跨接口通信。
